# 慧眼智检 · 线缆质量管控平台

基于现有订单/工单、线缆盘与检测任务进行采集、追溯和质量展示。当前采用 React / TypeScript、Node.js / TypeScript / NestJS、PostgreSQL 与独立 Go 边缘采集端。

## 当前应用

| 应用 | 入口 | 职责 |
|---|---|---|
| 业务前台 | http://127.0.0.1:4181 | 工单、多盘多任务、检测、历史、报警与报告 |
| 管理后台 | http://127.0.0.1:4182 | 共用身份系统，维护账号、非业务设置、审计和诊断 |
| 平台 API | http://127.0.0.1:4192/api/v1/health/ready | 接收、鉴权、业务查询、结果持久化 |
| 数据模拟平台 | http://127.0.0.1:4196 | 线缆预设、设备、送料、扫码枪模拟 |
| 边缘入口 | http://127.0.0.1:4198 | Go 现场采集程序的本地代理入口 |

检测中心有搭盖率、铜丝间隙、不圆度、护套厚度四个展示入口。护套复用双测径任务与配对结果；其“配对有效”不等于质量合格。中心使用时间轴，原始记录、规则快照和模拟/真实来源分别保留。

## 数据与可靠性

业务数据来自 API 和数据库。PostgreSQL 保存业务、判定及预计算统计；中心 InfluxDB 保存 OVALITY 原文与值。Go 边缘使用 bbolt 原始账本、本地时序和确认后出队机制。

已有设备/任务绑定、稳定来源键、唯一约束、逐条回执、重试及账号权限基础。真实设备能力、正式阈值、持续并发吞吐、联合灾备和客户 MES 尚需分项验收。analysis-worker 目前仅提供健康心跳，不能代表分析任务已执行。

## 开始开发

先读 AGENTS.md、.prompt.md 和目标工作包，执行各子工程的安装、构建与测试；命令见 [开发验证](docs/DEVELOPMENT.md)。不要在根目录运行 npm test 作为全项目验证。

当前后端部署必须组合 `docker/b1.compose.yaml` 与 `docker/ts01.compose.yaml`。已有数据库存在迁移校验漂移，升级前按 [运行部署](docs/OPERATIONS.md) 核查；不要直接重跑旧初始化或删除数据卷。

账号和令牌由本地受控配置提供。本轮不新增运行凭据、客户参考原件、数据库备份、现场数据、个人截图或构建依赖。原始设备资料继续保留在本地授权目录；远程仓库已有的历史原型和归档不代表当前运行实现。

## 版本与交付边界

本地外层应用源码与内层历史 Git 目录曾分离。HWREADY01 发布分支纳入当前应用源码、Go 边缘和正式文档，并用文件哈希记录快照；历史内层提交号不能代表当前外层源码。发布源码不等于部署，本轮审查没有重启平台或修改生产规则。

工程无统一生产放行声明；各页面、API、模拟、HW 分别登记，自测通过仍待用户验收。
