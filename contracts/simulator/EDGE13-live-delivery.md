# EDGE13 local custody and realtime view
2026-11-02. Existing /edge/v1/measurements remains center-confirmed for old producers. New routes use the same EDGE_INBOUND_TOKEN authentication.

POST /edge/v1/measurements:accept accepts the existing measurement batch (1..500, body <=1MiB). Atomically persists original identity/digest, samples and gatewayPending before returning {schema_version:"edge-local.1",batch_id,items:[{device_id,source_id,sample_id,status:"LOCAL_DURABLE"}]}. LOCAL_DURABLE is bbolt custody, not an InfluxDB or center STORED receipt. Retrying identical original records returns the same sample identity; changed content is rejected.

POST /edge/v1/measurement-receipts receives {records:[{device_id,record_id}]} and returns {schema_version:"edge-receipts.1",items:[{device_id,source_id,local_durable,receipt}]}; receipt is null until a persisted terminal center acknowledgement exists. Query is read-only. Producers retain raw source payloads and center-PENDING state until this acknowledgement. SQLite edge_local_accept records separate local custody; a missing local record on lookup clears the marker and makes the original eligible for resend. Manual drain/replay may deliver retained records of stopped runs; receiver still enforces original cutover times and identities.

GET /api/live is the local UI SSE channel. Each data frame has runId, reset, cursor, rows, time and optional state (including UI CSRF, same local-host boundary as /api/state). First/reconnected frame resets the current 60-second view, maximum 30000 points; increments use monotonic sample IDs. Rows include id/runId/at/received/gauge/x/y/mean/ratio/valid/sheath. Task changes reset; gaps are never interpolated. Signals fire only after successful durable transactions. Server coalesces at 50ms; client at 100ms plus RAF. Heartbeats/state every ~1s, write timeout5s, <=8 viewers, nginx X-Accel-Buffering:no. Failed/stalled stream falls back to polling; fresh snapshots recover after reconnect. Source timestamps remain unchanged. Actual end-to-end latency depends on generation, network and rendering; these are batching targets, not a measured SLA.

Center gatewayLoop remains independent and waits for local InfluxDB projection before forwarding at its existing one-second cadence, preserving pending/receipt/rejected ledgers and source IDs. No central DB or measurement-rule migration.
