# SC03 重复扫码执行契约

2026-11-02；M02/M09/M10；已实现、部署，自测通过待用户验收。

## 1 生命周期（已完成）

| 扫描目标 | 处理 | 验收条件 |
|---|---|---|
| CREATED | 使用原任务及新绑定开始 | 第1次采集 |
| RUNNING | 结束设备当前执行，克隆冻结上下文并开始新执行 | 新任务ID、编号、绑定；原执行ENDED |
| ENDED | 创建新执行并开始 | 原记录不修改 |
| CANCELLED、错设备、过期归属 | 拒绝 | 当前执行和数据不变 |
| 同请求重试 | 返回原结果 | 不多建执行 |

仅OVALITY/SIMULATED；护套辅助数据与其同任务。设备按device_id校验；保留开机等待扫码、关机结束、每秒批量转发及历史补传。

## 2 接口与幂等（已完成）

中心接口沿用SC02，设备凭据与边缘凭据不变。模拟器扫码和边缘 /edge/v1/scan、/api/scan 增加可选request_id；网页每次成功扫码后生成下一请求ID，失败重试保留ID。边缘持久化请求指纹和待同步意图；相同ID不同内容拒绝。中心command_id继续由command_receipt去重。

label.order追加taskCode、scanRound、sourceTaskCode。边缘展示中心实际执行任务；不以条码文件名识别任务。

## 3 数据与展示（已完成）

- inspection_task.context_snapshot.scan_execution：source_task_id、source_task_code、previous_task_id、round。首轮没有此扩展时按第1次显示。
- 新执行沿用来源任务的冻结判定规则，关联当前盘号/工单。原业务记录、采样、绑定和快照不覆盖；追加TASK_SCAN_REPEAT审计。
- 每次新执行在工单/任务列表独立一行、独立历史；显示采集次数和来源任务链接。按来源编号搜索可查到同族执行。
- 计划申请不重复新增；任务数表示执行次数，不能当盘数或产量。盘号去重仍沿用现有逻辑。
- 原送料停止，新送料选择新执行。旧采样迟到仍归旧任务/绑定，不能写入新执行。
- 无新表或迁移。PG保留业务/判定/索引，OVALITY值/原文沿用TS01中心Influx。
