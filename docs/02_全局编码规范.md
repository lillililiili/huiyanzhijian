# 全局编码规范

版本：V0.3，2026-10-10。以下是正式开发的技术栈无关规范草案。现有原型为历史演示实现，不因不符合拟定目录或字段命名而在文档审查中整体重写。

## 目录与命名

按业务模块归组，模块内部再分层。平台、设备端、前端不共用一套包含业务逻辑的巨型工具库。建议目录见架构文档，审批前不批量创建业务目录。

| 对象 | 命名约定 |
|---|---|
| 模块编号与逻辑目录 | `M04` 与 `m04-measurements`，编号稳定，名称可描述性调整 |
| 数据库表与字段 | `snake_case`，表归属以数据库设计为准 |
| HTTP JSON 字段 | `snake_case`，供应商原字段只留在原始数据和适配器内 |
| 类型与接口 | 语言允许时 `PascalCase`；公开能力以职责命名，如 `MeasurementApi` |
| 方法与变量 | 遵守获批准语言惯例，全项目由格式化和静态检查统一 |
| 请求与响应 | `CreateTaskRequest`、`TaskResponse`，一个名称对应一个用途 |
| 内部传输对象 | `TaskSnapshotDto`；只在需要转换或跨边界传输时建立 DTO |
| 数据实体 | `InspectionTaskEntity` 或语言等价形式，仅持久化层使用 |
| 领域值对象 | `VO` 专指 Value Object，不同时指页面展示对象；页面模型称 ViewModel |

公开契约字段不能因为本地代码改名而悄悄改变。专有缩写写入领域术语或模块文档。

## 分层职责

1. 入口层解析请求、调用鉴权、校验基础格式、映射统一响应，不编写测量计算或数据库查询。
2. 应用层编排用例、权限和事务；调用领域规则及模块公开接口。
3. 领域层处理状态迁移、测量和判定不变量，不访问网络、数据库或界面。
4. 基础设施层实现仓储、设备协议、文件与外部通信；通过依赖注入提供给上层。
5. 持久化实体不直接序列化为外部响应。每个响应只暴露该用例允许的字段。

纯查询可以直接返回明确的只读 DTO，不为简单字段机械创建层层转发类。复杂模块可以有内部子模块；外部只面对已登记接口。

## 模块之间的调用

- 使用模块公开接口和显式依赖注入；不直接实例化、导入或反射访问其他模块内部服务与仓储。
- 仓储仅访问所属模块表。跨模块取数据通过公开查询或接收事件建立本模块投影，不跨表写 SQL。
- 同步业务依赖和异步事件均遵守架构文档的允许依赖表。事件不能成为绕开边界的隐藏调用。
- 事件发布与业务提交的一致性、消费去重必须设计清楚；异步失败不回滚已发生的测量事实。
- 共享目录只放契约、基础技术能力和纯展示组件，不把任务、配方、判定或报警逻辑挪入 `common`。
- 前端特性目录只调用所属模块或已批准的公开 HTTP 接口，不读取另一个特性的内部状态存储。

## 返回值、异常和日志

统一响应、HTTP 状态和错误码以 [接口总契约](05_接口总契约文档.md) 为唯一规范。

业务异常携带错误码、可安全显示的信息和必要字段提示；统一异常处理器负责映射响应。意外异常记录服务端堆栈，对外返回通用提示与 `request_id`。不采用全局捕获后返回空集合、零值或成功状态的方式掩盖失败。

日志至少包含时间、级别、模块、追踪号、设备或任务标识及事件类型。禁止记录口令、完整令牌、连接串密钥。高频原始样本进入数据存储，避免逐条 INFO 日志造成资源压力。

## 数据与判定

- 内部 ID 与外部工单、盘号分开保存。跨工厂查询必须带数据范围并在服务端校验。
- 业务阈值属于批准的配方版本；不写死在页面、常量类或设备驱动中。
- 稳定技术常量使用枚举或有语义名称的常量；不为明显的数学常数建立多余类。
- 使用批准的十进制处理策略；完整精度判定、格式化仅用于显示。禁止先四舍五入再判断超限。
- 无数据、无效、陈旧和零值分别处理。无米数为 `null` 和位置状态，不补零。
- 重试沿用稳定记录键，不以数值相同判断重复采样。原始测量不可被人工处置覆盖。
- 对于时钟偏差、序号回绕、重启和乱序，按设备协议制定来源身份规则，写入模块文档和测试。
- 原型字段经边界映射为正式契约；状态转换显式处理 `invalid→有效性+未判定`，不把 `resolved` 静默视为已复核。详见第 08 份文档。
- 统计、筛选、分页与导出使用同一口径和截止点。不同单位、方法、窗口的均值分组计算；采样降频只影响展示，异常点和原始记录保持可定位。
- 人员、审核时间、工厂范围由服务端验证或生成；前端输入的“处置人”只可作备注，不能作为责任身份。
- 正式业务测试覆盖服务端越权、批次审核/更正、事件滞后和报告快照。原型测试中的 localStorage、任意密码、模拟 MES 确认不能迁入生产逻辑。

## 注释、依赖与文件范围

公开类型说明职责和边界；核心方法说明输入条件、不变量、副作用及失败行为。Java 使用 Javadoc，其他语言使用等价文档格式。业务行注释解释原因，不逐行复述语法。

新增依赖、全局配置、路由入口、迁移文件、公共组件和锁文件必须在本次允许修改路径中。未经任务批准，不顺手格式化全仓库、升级依赖或重构已交付模块。

## R01语言映射与页面测试

第11份推荐Java＋Vue方案待批准：Java类型PascalCase、成员camelCase、包名小写；Vue单文件组件PascalCase，TypeScript内部camelCase，HTTP DTO字段继续snake_case。跨边界显式转换，不能随前端命名改API。Java持久化实体与公开DTO分开，TS生成类型不手改。依赖版本以G00验证后的锁/BOM为准。

## 测试与完成

测试围绕公开行为和风险，避免复制实现。关键计算覆盖低于/等于/高于阈值、无效值、分母为零、单位转换和舍入边界；数据链覆盖重复、乱序、断线恢复、换盘和越权。

模块测试用公开接口和设备样例验证。修复缺陷先复现，增加能在旧版本失败、修复后通过的回归用例；纯重构验证可观察行为不变。

页面交互须在真实浏览器实际执行并回读任务、状态或结果；构建和单元测试作为辅助证据。真机能力与 MES 业务接收另行核验，模拟器结果不能替代。

以页面工作包组织交付和浏览器用例，UI模拟、API真实业务、HW真机分别留证据并更新第12份。模块仍保留各自公开行为测试，不为页面拆分复制业务逻辑或关闭跨页回归。

交付前检查 `git diff` 中每个文件是否在任务范围，核对新模块与旧模块的影响，更新模块文档。具体冻结流程见风险与约束。
