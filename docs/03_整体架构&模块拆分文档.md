# 整体架构与模块拆分

版本：V0.3，2026-10-10，待评审。以下是正式系统的逻辑模块划分；现有原型源码尚未按此结构实施。模块可以包含自己的前端页面、后端入口、业务与仓储，不按“前端一个大模块、后端一个大模块”切分全部业务。

## 架构与替代方案

建议平台采用模块化单体：部署简单、事务范围清楚，通过包边界和公开接口控制耦合。设备端独立进程运行，以适应断网和现场硬件。

直接做不分模块的单体虽然初始化较少，但容易让页面、规则和存储互相引用；本项目不采用这种组织建议。微服务可独立部署，但会增加一致性、运维与故障处理成本；当前没有规模依据，暂不作为首期建议。最终技术方案由 T01/T08 评审确定。

## 文字架构与数据方向

```text
浪潮产品1/2 → M08 供应商适配 → M04 统一接收与记录
共久硬件 → M09 本地采集、判定、落盘、上传 → M04
M01 设备与产品档案 → M02 检测任务 ← M03 已批准配方
M04 记录与有效性 → M05 报警处置 → M06 追溯与报告
M04/M05/M06 的已提交事件 → M07 MES 出站队列 → 客户 MES
M10 前端壳装配各业务模块页面；人员权限与审计由 M00 提供
```

平台断网：M09 使用已缓存且适用的批准配方检测，先本地落盘并保留上传队列。平台/MES 未确认的数据不删除。没有可用任务和规则时按明确策略暂停正式判定，不自动套用旧盘号。

## 模块清单与公开接口

表中接口名是建议的稳定逻辑名称；方法的具体 DTO、错误和路径由全局契约及模块文档细化，接口名不表示已实现。

| 编号与名称 | 职责与公开能力 | 输入与输出 | 不负责 |
|---|---|---|---|
| M00 身份权限与审计 | `IdentityApi`、`AccessApi`、`AuditApi.append/query`；`SystemConfigApi` 非业务平台配置与运行健康 | 身份/动作/资源范围→授权结果；配置版本/审计/健康状态 | 工艺规则、质量判定；把配方和 MES 配置放万能设置表 |
| M01 生产与设备档案 | `CatalogApi.getDevice/getSpecification/getContext`；维护工厂、产线、工序、设备、规格 | 档案输入→稳定内部标识和状态 | 检测任务状态、采样协议解析 |
| M02 工单盘号与检测任务 | `TaskApi.create/start/pause/resume/end/getSnapshot`；维护工单、盘号、线芯标识、计划长度与任务切换 | 已存在设备/规格和配方→单指标任务及创建时冻结快照；暂停恢复待 T10 | 改写测量数据、把任务结束判为整盘合格 |
| M03 指标方法与配方 | `RuleApi.getApprovedSnapshot/evaluate/validateRecipe`；规则批准与版本 | 指标、有效数据、方法和配方版本→判定及依据 | 设备驱动、未经确认的不圆度公式 |
| M04 数据接收与测量记录 | `MeasurementApi.ingest/ingestSourceAlarms/query/get/export/getCoverage`；`ImportApi.validate/commit/review/void/correct`；`EvidenceApi`；`DeviceStatusApi.heartbeat/query` | 设备/人工/文件来源→记录、审核与有效版本、覆盖、运行状态和证据 | 报警处置、MES 网络请求、覆盖历史事实 |
| M05 报警与质量处置 | `AlarmApi.query/acknowledge/recordAction/review` | 测量超限或设备故障→事件、确认、恢复及处置轨迹 | 采集、直接改变原测量为合格 |
| M06 追溯、统计与质量报告 | `TraceApi.getSpool/getMeasurementTrace`；`AnalyticsApi.query/export`；`ReportApi.generate/get/publish`；`TemplateApi.revise/getVersion` | 同截止点的只读数据→分组统计、阶段/任务最终/盘汇总报告与模板快照 | 修改原数据、混合不同口径均值、产品自动放行、第三方认证 |
| M07 MES 输出与对账 | `MesApi.getDelivery/getRecordSummary/retry/reconcile`；`MesConfigApi.get/update/check` | 测量/报警/报告事件→版本化映射、队列、业务回执与逐次发送轨迹 | 生产控制、默认 MES 工单下发、阻塞现场检测 |
| M08 浪潮接入适配 | `AdapterApi.getStatus/replay/getConfig/updateConfig/check`；供应商专用驱动对外仅规范化记录 | 按设备版本化接入配置和两款协议→统一上传包、能力缺项和诊断 | 重写浪潮算法；因原型菜单就宣称支持 MQTT/OPC UA |
| M09 共久设备端 | `EdgeApi.getStatus/selectTask/getRecentRecords`；只读驱动、现场报警、持久化与补传 | 共久实际读数、任务/配方快照→现场结果和稳定上传记录 | 依赖平台在线才能检测、未经授权写控制寄存器 |
| M10 前端壳与展示基础 | `ShellApi.registerFeature/registerNavigation`；登录入口、导航、通用表格/图表展示组件 | 功能注册与会话状态→页面容器 | 在公共图表组件内计算搭盖率或质量结果 |

M00 设备上传身份接口返回设备标识与范围；设备本身的档案状态由 M01 提供，避免 M00 反向依赖全部业务。基础设施中的日志、连接池、文件驱动和事务工具不是额外业务模块。

## 允许依赖表

“依赖”包括源码调用、数据读取、同步接口和事件消费。未经列入的业务依赖默认不允许；模块内部可以细分，但不暴露内部实现。

| 消费模块 | 允许的公开依赖 | 关键限制 |
|---|---|---|
| M00 | 无其他业务模块 | 审计输入携带资源标识，不反查所有业务 |
| M01 | M00 | 只管理本模块档案 |
| M03 | M00、M01 的规格查询 | 不访问任务、记录和报告 |
| M02 | M00、M01、M03 | 创建时保存指定批准版本快照；开始时复核同一快照，不读取配方内部表或静默换版 |
| M04 | M00、M01、M02、M03 | 校验设备、任务、快照与方法；上传处理不直接调用 M05/M07 |
| M05 | M00、M02、M04 | 消费测量事件或源设备报警；只写自身处置表 |
| M06 | M00、M01、M02、M03、M04、M05 | 通过批量只读接口取得快照，不跨表 SQL |
| M07 | M00、M02、M04、M05、M06 | 消费事件及公开查询；其他模块不等待 MES 发送成功 |
| M08 | M00、M01、M02、M04 的 HTTP/公开接口 | SDK 与厂商字段不泄漏到平台领域层 |
| M09 | M00/M01/M02/M03/M04 的公开同步与上传契约 | 本地缓存断网可用；禁止链接平台内部服务实现 |
| M10 | M00 会话接口及各特性注册契约 | 页面由所属业务模块拥有；壳层不反向调用业务内部实现 |

各业务模块的前端展示允许使用 M10 纯展示组件；M10 通过注册元数据装配特性，不静态导入各特性业务实现。组合入口承担装配职责，列入独立受控共享路径，避免循环依赖。

## 组合页面与数据所有权

工作台、监控、任务详情、追溯页同时显示多模块数据。采用受控只读 `PageQueryApi` 组合入口（`composition/queries`）调用公开批量查询，不拥有业务表，不写入任务/测量/MES 状态。组合入口输出各块的 `as_of`、版本和错误状态，失败块显示不可用，不给整页虚构成功值。模块内写操作仍直接交由所属模块命令接口处理。

此入口可依赖 M00–M07 的公开只读能力，业务模块不反向依赖入口；前端仅依赖明确登记的页面查询契约。它解决“任务详情需要 MES 状态，但 M02 不能反向依赖 M07”的问题，不放宽跨模块 SQL 或允许循环依赖。

| 页面能力 | 唯一业务归属 | 组合/下游 |
|---|---|---|
| 工作台与监控汇总 | 组合入口装配；M01 档案、M02 任务、M04 测量/心跳、M05 报警、M07 同步各自负责 | M10 负责壳；卡片点击携带对象 ID 进入所属功能 |
| CSV/人工补录、审批、更正、记录导出 | M04 | 正式生效事件给 M05/M06/M07；待审核不进入正式统计 |
| 统计与报告模板 | M06 | 使用 M04 批量只读数据；模板只影响新报告 |
| 设备在线与最新数据 | M04 运行投影；M01 管理启停/能力/校准档案 | 档案页面通过组合入口展示两种状态，编辑档案不能设置真实在线 |
| 设备接入配置 | M08 浪潮绑定 / M09 设备端配置各自拥有 | 页面按设备与适配器分发，不能所有设备共用一个连接对象 |
| 系统设置 | M00 平台名称/机构/健康；M10 个人显示偏好 | 工厂时区 M01、指标显示 M03、模板 M06、MES M07 各自管理 |

报告内的质量数据由 M06 冻结；正式报告默认不冻结 MES 投递状态。任务/追溯/记录抽屉的 MES 状态由组合入口查询 M07 后展示，注明查询时间。原型报告 CSV 包含 MES 状态属于演示事实；若正式报告也需该快照，先在 T09 明确用途并设计受控快照输入，不增加 M06→M07 与 M07→M06 双向依赖。

## 公开交互细则

| 场景 | 调用或事件 | 事务与失败行为 |
|---|---|---|
| 创建/开始任务 | M02 创建时查询 M01 与 M03、保存快照；开始时复核绑定及并发占用 | 同设备 RUNNING/PAUSED 互斥；开始不换配方；状态转换和命令回执同事务，失败保持原状态 |
| 上传测量 | M08/M09 调用 M04 `ingest` | 身份、结构、去重、任务及规则检查；成功回执仅在记录持久化后返回 |
| 计算与记录 | M04 使用 M03 明确方法/版本处理；M09 保留同版本现场判断 | 记录源判断和平台结果；冲突隔离并显示差异，不覆盖原值 |
| 产生报警 | M04 提交后发 `MeasurementStored.v1` 或 `SourceAlarmReceived.v1`，M05 消费 | 消费幂等，事务失败可重放；本地报警不等待此事件 |
| 报告发布 | M06 读取明确截止时点与规则版本的数据 | 报告保存统计依据、输入范围和版本；迟到数据另出版本 |
| MES 推送 | M07 消费测量、报警变化、报告发布事件 | 独立重试；业务拒绝和网络错误分开；发送成功不改原测量 |
| 补录生效/更正 | M04 审核/更正后发布 `MeasurementEligibilityChanged.v1` | M05 更新处置待办；M06 标记报告数据已变化；M07 按 T05 更正契约处理，不用重试覆盖旧载荷 |

发布模块各自拥有事务 outbox 和消费收据，平台只提供通用调度能力。M04/M05/M06 等模块不共用一张跨模块可写的“万能事件表”。消息字段见接口总契约。

## 页面交付与模块边界

页面是派工和提测单位，模块是源码、接口与表归属单位。按第12份Pxx工作包交付完整页面子范围，包含必要前后端及测试数据；一个A会话可实现明确列入范围的多个未冻结模块增量。已验收路径和行为保持冻结，旧Bug交独立B会话，C设计下一页。不得为逐页开发放宽跨模块内部调用或跨表SQL。

页面依赖的是公开能力，不是其他模块全部完成。例如P09规格先测保存与权限，P07完成后再联合验证禁用规格不可选；P21档案先测，运行状态等G01后补。未交区块必须声明，不能把子范围验收等同全页或全模块冻结。工程路径和候选工具见第11份；当前可测状态只在第12份登记。

## 边界验收

设计审查检查依赖图无业务循环、每表只有一个写入归属、事件只有一个发布定义。工程建立后使用语言对应的静态检查和导入规则阻止越界；契约测试验证正常、无权限、重复、版本不支持和恢复行为。尚未建立 CI 时标明未自动执行，不能声称文档本身阻止了跨模块修改。
