## 类型、公共字段与归属

| 记法 | 逻辑含义 | 实施时要求 |
|---|---|---|
| ID | 不透明内部标识 | 建议 UUID；物理类型由 T01 固定 |
| S(n) / TEXT | 最长 n 字符的字符串 / 长文本 | 明确编码、大小写与业务编码比较方式 |
| I32 / I64 / BOOL | 整数 / 长整数 / 布尔 | 不把空值当零；枚举用有语义的字符串 |
| DEC(p,s) | 定点十进制 | 暂定通用值 DEC(24,10)，精度需结合 T04 样本确认 |
| TS | 带统一时间基准的时间点 | 存储 UTC，保留来源时间偏移或时区信息 |
| JSON | 有版本结构的数据 | 仅用于协议原文、快照、辅助数据，不替代关键检索列 |
| `?` | 允许为空，默认 NULL | 其余字段非空且无默认值，必须显式赋值 |

以下每张业务表均包含 `id ID PK`、`created_at TS`，由所属模块生成。标为“可变”的表另含 `updated_at TS`、`version I64 DEFAULT 1`；可变表更新进行乐观锁校验。“版本追加”表在草稿编辑、审批或投递等生命周期字段允许更新时，也包含这两个并发字段；内容冻结后仅允许明确列出的生命周期字段改变。测量原文、已批准规则内容、审计和已生成报告内容采用追加或新版本，不能覆盖。

每张表只允许所属模块写入。同模块关系在确定数据库后优先建立物理外键；跨模块 ID 是逻辑引用，通过公开接口校验和快照保留，不开放跨模块仓储。本文所有关联均列出，跨模块不默认级联删除。

工厂范围是服务端授权约束。除全局身份/字典和本地端表外，业务数据携带 `factory_id`；子项可以从所属记录继承范围，但查询必须经过所属模块验证。外部工单和盘号按已确认唯一范围建索引，不把名称作为主键。

## R01建议物理映射

候选PostgreSQL映射：ID→uuid，TS→timestamptz，DEC→numeric，JSON→jsonb，I32/I64→integer/bigint；字符串保持长度约束，来源时区另存。M00人员会话建议Spring Session JDBC管理的技术表，设备凭据仍用access_credential；技术表由G00单独登记，不暗中替代业务表归属。迁移按页面必需增量建立，不一次性创建全部逻辑表。此映射仍待R01-Q01及G00验证。

## M00 身份权限与审计

### app_user 可变

| 字段 | 类型 | 含义 |
|---|---|---|
| login_name | S(128) | 登录名 |
| display_name | S(128) | 显示姓名 |
| auth_provider | S(32) | 已批准身份方案 |
| external_subject | S(256)? | 外部身份标识 |
| password_hash | S(512)? | 仅本地密码方案使用的安全哈希，不存明文 |
| status | S(16) | ACTIVE / DISABLED |

唯一索引：`login_name`；外部身份方案另设 `(auth_provider,external_subject)` 的非空唯一约束。身份方案在 T01 确认前不实现密码存储策略。

### app_role 可变

字段：`code S(64)` 角色码；`name S(128)` 名称；`permission_codes JSON` 允许动作码列表；`status S(16)` 状态。

唯一索引：`code`。权限码在模块文档登记，不能由任意客户端字符串创建权限。

### user_role 可变

字段：`user_id ID` 用户；`role_id ID` 角色；`scope_type S(16)` SYSTEM / FACTORY；`scope_key S(64)` 全局固定键或工厂内部 ID 字符串。

同模块 FK：`user_id→app_user.id`、`role_id→app_role.id`。FACTORY 范围逻辑指向 M01 工厂。唯一索引：`(user_id,role_id,scope_type,scope_key)`；索引 `user_id`。scope_key 不为空，避免 NULL 破坏范围唯一约束。

### access_credential 可变

字段：`actor_type S(16)` USER / DEVICE；`actor_id ID` 身份主体；`credential_hash S(512)` 验证摘要；`scope JSON` 受控权限范围；`expires_at TS?` 到期时间；`revoked_at TS?` 撤销时间；`credential_version I64` 轮换版本。

索引：`(actor_type,actor_id)`、`expires_at`；摘要唯一。设备 actor_id 逻辑指向 M01 设备。是否采用令牌会话、外部身份或其他机制由 T01 决定；此表不得被理解为强制自研 JWT 或明文保存密钥。

### audit_event 追加

字段：`factory_id ID?` 所属范围；`actor_type S(16)`、`actor_id ID?` 操作主体；`action S(64)` 动作；`resource_type S(64)`、`resource_id S(128)` 资源；`occurred_at TS` 发生时间；`request_id S(128)` 追踪号；`before_state JSON?`、`after_state JSON?` 脱敏前后状态；`reason TEXT?` 原因；`result S(16)` SUCCESS / FAILURE。

索引：`(factory_id,occurred_at,id)`、`(resource_type,resource_id,occurred_at)`、`request_id`。资源为逻辑引用；无级联删除。审计载荷禁止包含凭据和原始敏感报文。

### platform_config 可变

字段：`scope_key S(64)` 实例范围；`platform_name S(128)` 平台名称；`organization_name S(128)` 机构名称；`updated_by ID` 操作人。唯一索引 scope_key；人员引用 M00。只存非业务平台标识，不存配方/MES/时区或万能键值；运行健康由实际进程检查输出。

### specification_applicability 可变

字段：`specification_id ID` 规格；`process_id ID` 工序；`metric_code S(64)` 三项稳定契约码；`enabled BOOL DEFAULT false`。FK 规格/工序在 M01；唯一索引 `(specification_id,process_id,metric_code)`。禁用停止新任务使用，不删除历史适用依据；不依赖 M03 内部表。

字段：`factory_id ID` 工厂；`task_code S(128)` 任务编号；`work_order_id ID` 工单；`spool_id ID` 盘；`core_code S(64)?` 线芯/相别；`device_id ID` 设备；`process_id ID` 工序；`specification_id ID` 规格；`metric_code S(64)` 本任务唯一项目；`planned_length_m DEC(24,10)` 计划长度；`recipe_version_id ID` 批准配方；`recipe_snapshot JSON` 创建时冻结规则；`context_snapshot JSON` 创建时工单/盘/规格/设备/能力版本；`state S(16)` CREATED / RUNNING / PAUSED / ENDED；`started_at TS?` 开始；`ended_at TS?` 结束；`started_by ID?` 操作者；`end_reason TEXT?` 结束说明。

计划长度>0；任务匹配规格/工序适用性、设备能力与批准规则。开始时复核绑定和占用，不静默更换创建快照。原型 measuredLength 不能直接成为权威覆盖列：位置段/有效覆盖由 M04 查询输出。提前结束保留实际覆盖与原因，不补齐到计划长度；暂停恢复与异常取消规则待 T10，原型没有实现。

## M03 指标方法与配方

### metric_definition 可变

字段：`code S(64)` 指标码；`name S(128)` 名称；`unit S(16)` 单位；`value_kind S(16)` 数值类型；`display_scale I32` 展示小数位；`status S(16)` 状态。

唯一索引：`code`。本期业务指标仅预置三项；外径方向值保留为原始数据，不新增第四种检测菜单。变更单位属于契约变更。

### metric_display_config 可变

字段：`factory_id ID`；`metric_id ID`；`display_scale I32`；`description TEXT?`。工厂逻辑引用 M01，FK metric_id 在 M03，唯一索引 `(factory_id,metric_id)`。metric_definition.display_scale 为默认精度，工厂显示配置不改变值、单位或判定；报告冻结生成时显示精度。

### measurement_method 版本追加

字段：`method_code S(64)` 方法码；`method_version S(32)` 版本；`metric_id ID` 指标；`definition JSON` 公式/方向/窗口/输入定义；`approval_state S(16)` DRAFT / APPROVED / RETIRED；`approved_by ID?` 批准人；`approved_at TS?` 批准时间；`golden_sample_ref S(256)?` 黄金样本证据引用。

FK：`metric_id→metric_definition.id`；人员逻辑引用 M00。唯一索引 `(method_code,method_version)`。DRAFT 可受控编辑，APPROVED 内容不可原地更改，升级另建版本。

### recipe_version 版本追加

字段：`factory_id ID` 工厂；`specification_id ID` 规格；`process_id ID` 工序；`recipe_code S(64)` 配方码；`revision I32` 版本序号；`approval_state S(16)` DRAFT / APPROVED / RETIRED；`approved_by ID?` 批准人；`approved_at TS?` 批准时间；`snapshot_hash S(128)?` 批准快照摘要。

逻辑引用 M01 规格/工序和 M00 人员。唯一索引 `(factory_id,recipe_code,revision)`；索引 `(factory_id,specification_id,process_id,approval_state)`。批准后规则只读，任务引用明确版本，不能查“最新规则”代替历史依据。方法版本由 recipe_rule 明确关联；不得仅按指标选全局最新配方。

### recipe_rule 随配方版本冻结

字段：`recipe_version_id ID` 配方；`metric_id ID` 指标；`method_id ID` 已批准方法；`operator S(16)` 比较操作符；`lower_bound DEC(24,10)?` 下界；`upper_bound DEC(24,10)?` 上界；`window_definition JSON` 统计范围；`alarm_policy JSON` 持续时间/防抖等受控规则。

FK：以上三个 ID 均在 M03。唯一索引 `(recipe_version_id,metric_id)`。操作符与边界组合校验；不开放任意脚本。三项历史示例阈值须经 T04 批准才可录入正式配方。

## M04 接收、测量与证据

新增数据环境字段 `data_environment=REAL/SIMULATED` 与来源方式分开；原型所有数据均为 SIMULATED，即使显示“设备自动采集”或“人工导入”。

### measurement_record 原始部分不可变

字段：`factory_id ID` 工厂；`device_id ID` 设备；`source_record_key S(128)` 上传包 record_id；`source_record_id S(128)?` 供应商键；`source_session_id S(128)?` 设备启动会话；`source_sequence S(128)?` 源序号；`sample_kind S(24)` 新样本/读取快照；`task_id ID?` 已核实任务；`recipe_version_id ID?` 配方；`sample_time TS` 来源时间；`received_at TS` 服务端时间；`time_source S(24)` 时间来源；`source_timezone S(64)?` 源时区；`position_m DEC(24,10)?` 米数；`position_quality S(24)` 位置状态；`source_type S(24)` 数据来源；`data_status S(16)` 整体有效性；`receipt_status S(24)` 接收/隔离状态；`raw_payload JSON` 原始数据；`payload_hash S(128)` 去重摘要；`schema_version S(32)` 契约版本。

逻辑引用 M01/M02/M03。唯一索引 `(factory_id,device_id,source_record_key)`；索引 `(factory_id,task_id,sample_time,id)`、`(factory_id,device_id,received_at,id)`、`(receipt_status,received_at)`。

未知任务记录保留原输入于 raw_payload，task_id 为空且隔离；关联后通过追加关联记录处理，不改原输入。增加 `measurement_association` 表见下。保留重复数值的不同合法采样，不因值相同去重。

补全字段：`data_environment S(16)`；`import_batch_id ID?` M04 来源批次；`position_segment_id S(128)?` 换盘/计米复位段。data_status 指本任务指标有效性，不把辅助外径有效当成不圆度有效。批次 FK 在同模块建立；device_id 对人工记录表示绑定设备，不证明该设备自动测得。

### measurement_association 追加

字段：`record_id ID` 记录；`task_id ID` 核实任务；`actor_id ID` 操作人；`reason TEXT` 关联依据；`supersedes_id ID?` 被替代关联；`association_version I64` 关联版本。

FK：record_id 和 supersedes_id 在 M04；task_id 逻辑引用 M02。唯一索引 `(record_id,association_version)`。有效关联由版本查询取得；原始接收信息不可覆盖，更正同时审计。

### measurement_value 追加

字段：`record_id ID` 主记录；`metric_code S(64)` 指标码；`value DEC(24,10)?` 测量值；`unit S(16)` 单位；`data_status S(16)` 项有效性；`source_quality_result S(24)` 源判定；`quality_result S(24)` 平台受控判定；`method_id ID?` 方法；`recipe_version_id ID?` 配方；`window_definition JSON` 统计窗口；`reason_code S(64)?` 无效或未判定原因；`evaluation_version I32` 判定版本。

FK：`record_id→measurement_record.id`；方法、配方逻辑引用 M03。唯一索引 `(record_id,metric_code,evaluation_version)`；索引 `(metric_code,quality_result,record_id)`。仅 VALID 且方法已批准才可判 PASS/FAIL；重算另建版本，原判定保留。

辅助量（搭盖宽度/节距、局部间隙数组、X/Y 外径）保存在带版本 raw_payload 中，逐项含单位、有效性、来源和算法版本。方法未批准但设备给出有效指标时保留 value、判定 NOT_EVALUATED；指标未提供/无效才置空。图表、报警和报告必须绑定同一 evaluation_version。

### import_batch 可变

## 可靠事件表模板

这是基础设施模板，不是各模块共同可写的业务表。按模块实例化：M04 `measurement_outbox`；M05 `alarm_outbox`、`alarm_consumer_receipt`；M06 `report_outbox`、`report_consumer_receipt`；M07 `mes_consumer_receipt`。命令结果分别使用 `catalog_command_receipt`（M01，P09新建幂等）、`task_command_receipt`（M02）、`measurement_command_receipt`（M04）、`report_command_receipt`（M06）；其他模块按幂等策略决定是否复用自身动作表。未使用的表不提前创建。

### owner_outbox 可变投递状态

公共字段之外：`event_id ID` 事件；`event_type S(64)` 类型；`schema_version S(32)` 版本；`factory_id ID` 范围；`aggregate_id S(128)` 聚合；`aggregate_version I64` 版本；`occurred_at TS` 时间；`correlation_id S(128)` 追踪；`payload JSON` 不可变载荷；`state S(24)` PENDING / SENDING / SENT / MANUAL_ACTION；`attempt_count I32 DEFAULT 0` 次数；`next_attempt_at TS?` 下次；`lease_until TS?` 发送租约；`last_error TEXT?` 脱敏原因。

唯一索引 `event_id`；待发送索引 `(state,next_attempt_at,id)`。业务事实和所属 outbox 在同一模块本地事务写入。SENT 表示交给可靠消费机制，不代表 MES 业务成功。

### owner_consumer_receipt 追加

字段：`consumer_name S(128)` 消费者；`event_id ID` 原事件；`aggregate_id S(128)` 聚合；`aggregate_version I64` 版本；`processed_at TS` 完成时间。

唯一索引 `(consumer_name,event_id)`；索引 `(aggregate_id,aggregate_version)`。消费收据与业务修改同事务提交；失败不提前写成功收据。其幂等保留期需覆盖事件重放窗口。

### owner_command_receipt 追加

字段：`factory_id ID` 范围；`actor_id ID` 调用者；`command_type S(64)` 动作；`idempotency_key S(128)` 幂等键；`request_hash S(128)` 请求摘要；`resource_id ID?` 产生资源；`response_snapshot JSON` 成功结果；`expires_at TS?` 到期时间。

唯一索引 `(factory_id,actor_id,command_type,idempotency_key)`。成功回执与业务写入在同事务提交；并发相同键只能有一个业务结果。同键不同内容报冲突；外部副作用另通过 outbox，不因请求重试重复执行。保留期限至少覆盖契约允许的重试窗口，审批前不自动清理。

## 迁移与保留约束

1. 选型后逐表补物理类型、索引长度、JSON 支持、唯一性与 NULL 行为、时间精度、外键及事务策略，评审后才编写迁移。
2. 迁移由表所属模块维护；新增模块不修改已发布旧迁移，不擅自跨模块改列。共享 ID 关系通过契约评审。
3. 大数据分区、索引覆盖、保留周期、批量大小依据 T06 的真实负载确定，不能提前承诺永久高频记录或无限图像。
4. 归档、作废和删除不是同一个动作。原始测量、已批准规则、审计和发布报告禁止普通业务接口硬删除；保留策略执行必须有范围、记录和恢复安排。
5. 测试必须覆盖同键同内容、同键异内容、相同数值的不同采样、跨工厂越权、任务并发开始、规则版本、离线补传、事件重复及备份恢复。
6. 本地和平台备份分别验证，恢复后检查任务、规则、原始记录、证据和发送状态关联。只恢复表行数不足以证明业务数据完整。
