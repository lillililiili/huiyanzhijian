# 接口总契约 api_spec

版本：V0.3，2026-10-10，待评审。原型只有静态 HTTP 服务与浏览器数据操作，以下业务 API 均尚未实现。27 页与接口映射见第 07 份文档；正式开工前目标模块需补可校验 DTO/Schema、边界值和契约测试，端点目录不是完整 OpenAPI。

## HTTP 与身份

建议平台接口以 `/api/v1` 开头，UTF-8 JSON 请求和响应；字段使用 `snake_case`。日期时间采用带 UTC 偏移的 ISO 8601，服务端存储统一时间基准。展示时区由工厂配置，不能用浏览器隐式时区改变采样含义。

| 请求项 | 约定 |
|---|---|
| `Content-Type` | JSON 写操作使用 `application/json` |
| 人员会话Cookie | R01建议服务端会话，HttpOnly；生产HTTPS使用Secure及明确SameSite；会话寿命/撤销由P01契约定稿，待R01-Q06确认 |
| CSRF请求头 | 使用会话Cookie的写操作校验CSRF，头名称及获取接口由G00/P01固定 |
| `Authorization` | 设备上传建议Bearer设备凭据；与人员会话隔离，限定设备范围、可撤销；不自行假定JWT |
| `X-Request-Id` | 可选客户端追踪号；服务端验证格式或生成，响应和日志返回同一号 |
| `Idempotency-Key` | 创建任务、发布报告等重试可能重复生效的命令必填；具体范围与保留期由模块说明 |
| `If-Match` | 修改可变资源时携带读取到的版本，版本冲突不覆盖他人修改 |

身份不从客户端传入的 `role`、`user_id`、`factory_id` 推断。每次操作校验会话或设备凭据、动作权限和实际资源所属工厂；设备身份限定可上传设备及工厂。浏览器登录存储方式、CSRF 与跨域策略在 T01 中一起确定。

可变资源查询响应带 `ETag`，其值对应资源 `version`；修改请求的 `If-Match` 使用该值。模块契约明确哪些命令要求版本，不能在前端遗漏后由服务端直接覆盖。

## 统一响应与错误

```json
{
  "code": "OK",
  "message": "成功",
  "data": {"task_id": "example-task", "state": "CREATED", "version": 1},
  "request_id": "example-request"
}
```

```json
{
  "code": "TASK_STATE_CONFLICT",
  "message": "任务状态已变化，请刷新后重试",
  "data": null,
  "request_id": "example-request",
  "field_errors": [{"field": "version", "reason": "VERSION_MISMATCH"}]
}
```

示例标识仅展示结构，不是生产 ID。单条成功返回 200/201；异步操作在请求或记录已可靠持久化后返回 202。质量不合格是业务结果，不把 `FAIL` 当 HTTP 错误。

| HTTP | 错误码示例 | 含义 |
|---|---|---|
| 400 | `REQUEST_INVALID`、`SCHEMA_VERSION_UNSUPPORTED` | 结构、字段或契约版本不支持 |
| 401 | `AUTH_REQUIRED`、`AUTH_EXPIRED` | 身份缺失或失效 |
| 403 | `ACCESS_DENIED` | 有身份但无动作/范围权限 |
| 404 | `RESOURCE_NOT_FOUND` | 资源不存在或按策略隐藏范围外资源 |
| 409 | `TASK_STATE_CONFLICT`、`RECORD_PAYLOAD_CONFLICT` | 状态冲突或同记录键出现不同内容 |
| 412 | `RESOURCE_VERSION_MISMATCH` | `If-Match` 不匹配 |
| 428 | `RESOURCE_VERSION_REQUIRED` | 应携带的 `If-Match` 缺失 |
| 422 | `RULE_NOT_APPROVED`、`UNIT_MISMATCH`、`TASK_BINDING_INVALID` | 格式正确但业务条件不满足 |
| 429 | `RATE_LIMITED` | 按公布策略限流，提供可重试时间 |
| 500/503 | `INTERNAL_ERROR`、`DEPENDENCY_UNAVAILABLE` | 内部故障或依赖不可用；不返回内部堆栈 |

错误码稳定，文案可调整。全局码在此定义，业务码在所属模块登记；客户端按码处理，不解析中文消息。

## 通用值与查询

- ID 使用不透明字符串，数据库映射待选型；外部工单、盘号单独保存。
- 十进制测量值在 JSON 中建议使用规范十进制字符串，避免不同语言的浮点误差；百分指标 `"12.5"` 表示 12.5%，不表示 0.125。
- 三项指标建议码为 `SHIELD_OVERLAP_RATE`、`WIRE_GAP`、`OVALITY`；外径方向原始值在 `raw` 中保留。最终码在 M03 批准后固定。
- 来源方式 `source_type=DEVICE/DERIVED/IMPORT/MANUAL`，环境 `data_environment=REAL/SIMULATED` 分开记录。原型全为 SIMULATED。旧草稿单一 `source_type=SIMULATED` 在已批准契约发布前修订；若已有消费者则须显式兼容映射。三项导入/补录由 M04 负责，审核规则见第 08 份文档。
- 有效性 `VALID/INVALID/STALE/MISSING` 与判定 `PASS/FAIL/NOT_EVALUATED` 分开。无效或无批准规则的项不得为 PASS。
- 大量测量查询采用游标分页，固定 `received_before` 与业务 `sample_from/sample_to` 窗口，稳定排序并返回 `items/next_cursor/has_more/as_of`。游标绑定工厂、过滤器、排序和截止点；不能被改筛选后继续使用。普通档案可用 `page/page_size/total`。页长、批量和导出上限待 T06，不提供无限制全量接口。
- `STALE` 是相对查询时点的新鲜度，通常作为 `freshness` 返回；不因时间流逝改写原始 VALID 样本。如果设备采样当时已陈旧，记录来源有效性/原因。所有统计附口径、时区和截止点。

## 测量上传包

建议路径 `POST /api/v1/measurements:ingest`，归属 M04。一次请求可批量上传；批量上限、字节数和超时由 T06 后确定。

```json
{
  "schema_version": "1.0",
  "records": [{
    "record_id": "example-stable-id",
    "device_id": "example-device",
    "source_record_id": "example-source-id",
    "source_session_id": "example-device-boot-id",
    "source_sequence": "158",
    "sample_kind": "NEW_SAMPLE",
    "task_id": "example-task",
    "sample_time": "2026-10-09T14:00:00Z",
    "time_source": "DEVICE",
    "position_m": null,
    "position_quality": "UNKNOWN",
    "source_type": "DEVICE",
    "data_environment": "SIMULATED",
    "data_status": "MISSING",
    "recipe_version_id": "example-recipe",
    "values": [{
      "metric_code": "OVALITY",
      "value": null,
      "unit": "%",
      "data_status": "MISSING",
      "source_quality_result": "NOT_EVALUATED",
      "method_id": null,
      "window": {"kind": "INSTANT"},
      "reason_code": "METHOD_NOT_APPROVED"
    }],
    "raw": {"schema_version": "diameter-aux.v1", "data_status": "VALID", "diameter_x_mm": "40.12", "diameter_y_mm": "40.05"},
    "evidence_refs": []
  }]
}
```

该示例表达“辅助外径有效、目标不圆度未提供且方法尚未批准”。整体 MISSING 对应目标指标，不与辅助 raw 的 VALID 混淆。若设备已给出有效不圆度，即使方法未批准也保留数值并返回 NOT_EVALUATED，不能把真实值清空。raw 按方法/协议版本定义；不提供临时公式或合格结论。

| 字段组 | 校验与所有权 |
|---|---|
| 记录身份 | `record_id` 由采集源稳定分配，重传不变；以授权范围+设备+记录键唯一 |
| 采样身份 | 源序号/重启会话/原始记录号按协议取值；无新样本标识时 `sample_kind=READ_SNAPSHOT`，不冒充新采样 |
| 工厂与任务 | 工厂从设备身份得到；任务归属和当时快照由 M02 核验；无法关联的记录隔离待处理，不猜盘号 |
| 时间 | `sample_time` 与服务端 `received_at` 分开；源无时钟标注采集端时间来源 |
| 位置 | 无位置为 null/UNKNOWN；复位/倒退有独立状态，不跨工序硬拼米数 |
| 规则 | M03 方法和批准版本可验证；源判定原样保留，平台判定单独保存 |
| 证据 | 引用先由 M04 证据接口登记，校验所属范围和可访问性；不信任客户端任意外链 |

单任务单指标；values 保留数组形态用于契约扩展，但本期只允许匹配任务的一个业务指标，X/Y 等进入 raw。数值判定采用完整精度。客户端不能通过 `data_environment=REAL` 自行解除模拟身份：服务器按环境/凭据/接入配置验证来源。

## 接收回执与幂等

批量回执每条包含 `record_id`、`receipt_status`、`stored_record_id`、`error_code`；状态为 `STORED/DUPLICATE/QUARANTINED/REJECTED`。

- `STORED` 表示已持久化且满足接收条件，不等于质量合格或 MES 已接收。
- `DUPLICATE` 表示同键同内容；返回原记录引用，不新增或重复统计。
- `QUARANTINED` 表示原始数据已可靠保留、需要人工或规则关联处理，不能计入正式合格统计；设备端按独立留存策略保存本地副本。
- `REJECTED` 表示未接收，返回逐条原因；客户端按原因修正或保留待处理，不能删除本地原始记录。
- 同键不同内容返回逐条 `RECORD_PAYLOAD_CONFLICT`，保留冲突证据，不覆盖原记录。整个单条命令冲突使用 HTTP 409；批量部分错误使用成功的批量回执加逐条状态，不将全部记成功。

去重摘要采用已版本化的规范化字段序列化；在契约测试中固定空值、字段顺序和十进制的等价处理。样本键按真实来源确定，不能只用时间戳或相同数值。

## 独立设备报警上传

设备断线、仪表故障等事件可能没有测量记录，不能要求伪造一条测量才能上传报警。M04 提供建议路径 `POST /api/v1/source-alarms:ingest`，接收 `schema_version` 与 `alarms` 数组。

每个事件包含稳定 `source_event_id`、`device_id`、`source_alarm_key`、`event_kind`（TRIGGERED/RECOVERED/ACKNOWLEDGED）、`occurred_at`、`source_type`、`data_environment`（REAL/SIMULATED）、`alarm_type`、`severity`、`message`；`task_id`、`record_id`、`source_sequence` 和 `raw` 可按实际能力提供。平台确认与设备本地确认分别留痕，不能把源确认当作平台人员的质量处置；环境从认证上传范围核验并贯穿报警查询、统计及事件，不信任客户端改标为 REAL。

设备身份校验与逐条回执沿用测量接收规则。M04 在本地事务保存 `source_alarm_record` 并写 outbox，M05 消费 `SourceAlarmReceived.v1` 形成业务报警。`source_event_id` 标识一次触发/恢复事件，`source_alarm_key` 关联同一报警生命周期；重发事件不生成第二条报警。乱序依据已确认的源版本/序号处理，缺少可靠顺序时显式记录状态待核实，不用接收顺序冒充设备发生顺序。

### 三个关键命令的字段与失败契约

**创建任务**：`POST /tasks` 必填 `work_order_id/spool_id/specification_id/process_id/device_id/metric_code/recipe_version_id/planned_length_m`，可选 core_code。工单/盘还不存在时使用 M02 独立建档命令，不由客户端猜 ID。服务端校验同工厂、规格工序适用、配方批准及相容性，创建时冻结规则和上下文；返回 task_id/task_code/state=CREATED/version/snapshot_hash。重复幂等键同内容返回原任务，异内容409。开始任务携带 Idempotency-Key/If-Match，设备占用409，绑定失效422；暂停、恢复分别用 `:pause`、`:resume`，T10 批准后才实现。

**导入**：validate 输入 `template_version/source_type/data_environment/timezone/reason` 及受控文件或 rows；返回 batch_id/version/validation_token/total/valid/invalid 与原始行号错误。commit 输入 validation_token、明确提交的行号集合、Idempotency-Key/If-Match；服务端重新校验任务/源键/版本，返回每行 STORED/DUPLICATE/REJECTED 和 qualification=PENDING_REVIEW。校验令牌与文件 hash、规则版本、操作范围绑定。不能把预览“通过”当已审核。跨任务允许逐行提交但结果必须完整列出，失败行重试不重写成功行。

**报告生成与发布**：POST /reports 输入 `report_kind/task_ids/spool_id/template_version_id/sample_from/sample_to/received_before/data_environment`；服务端验证同盘/工厂与工序线芯范围，冻结规则、判定版本、审核版本、处置、覆盖和格式。持久化生成任务后202返回 report_id/state；生成失败可查询原因，重试保留幂等语义。发布命令带 If-Match/Idempotency-Key；返回发布版本/快照摘要。阶段、任务最终、盘汇总前提见第 08 份文档；MES成功不是生成/发布条件。

新增业务错误码建议：`DEVICE_OCCUPIED`、`IMPORT_VALIDATION_EXPIRED`、`IDEMPOTENCY_PAYLOAD_CONFLICT`（409）；`SOURCE_NOT_ALLOWED`、`IMPORT_REVIEW_REQUIRED`、`REPORT_INPUT_NOT_READY`、`REPORT_SCOPE_INVALID`（422）；错误必须返回 request_id 和可恢复入口。缺 If-Match 为428，版本不一致412。

报警 `:handle` 的 action 必须明确为 START_PROCESSING 或 SUBMIT_HANDLED；`:review` 的 decision 为 APPROVE 或 REJECT，驳回回到 PROCESSING，均携带原因及资源版本。服务端记录认证 actor 并校验 BR07 转换与 BR11 职责，不能接收任意 status 值覆盖整条报警。

表内所有路径均接 `/api/v1`；`:start/:pause/:resume/:end` 是四个独立命令的简写，不是一个实际路径。M08/M09 的本地维护接口按现场鉴权另行设计，不直接向公网暴露。端点必须在模块文档中展开完整入参、出参和异常后才算可实施契约。

## 事件与可靠协作

事件共有 `event_id/event_type/schema_version/occurred_at/factory_id/aggregate_id/aggregate_version/correlation_id/payload`。重发 event_id 不变；消费方在本地事务中去重并处理，失败可重放，不能承诺全局严格顺序。

| 发布方 | 事件 | 最小载荷 | 消费方 |
|---|---|---|---|
| M04 | `MeasurementStored.v1` | 记录ID、任务ID、有效性、指标判定摘要、规则版本 | M05/M06/M07 |
| M04 | `SourceAlarmReceived.v1` | 设备、源报警键、发生时间、类型、关联记录 | M05 |
| M05 | `AlarmChanged.v1` | 报警ID、任务ID、生命周期、处置状态、版本 | M06/M07 |
| M06 | `ReportPublished.v1` | 报告ID、版本、任务范围、截止时间 | M07 |
| M04 | `MeasurementEligibilityChanged.v1` | 记录ID、资格版本、判定版本、原/新资格、替代记录、任务、原因 | M05/M06/M07 |
| M04 | `DeviceStatusChanged.v1` | 设备ID、连接/新鲜度状态、观察时间、会话、版本 | M05 |

MeasurementStored 表示存储事实，附 `data_environment/eligibility/evaluation_version`。M05/M06/M07 只消费满足其规则的有效正式版本；待审核/隔离不能因收到 Stored 事件而正式生效。实时最新状态与历史判定分开。MeasurementEligibilityChanged 触发报警证据更正提示、报告重出提示与 MES 更正/撤销流程，不抹去既有历史。报告生成需检查相关消费水位，防止测量已经写入但报警尚未生成就发布报告。

实际消费只按模块实现需要启用；同一次事实不能同时以两个不一致来源重复生成报警。消费者按聚合版本处理乱序或读取最新快照；发送顺序不能当作唯一正确性保证。

## MES 契约与兼容

内部规范消息与客户 MES 格式分别版本化，由 M07 映射。发送状态为 `PENDING/SENDING/RETRY_WAIT/ACKED/REJECTED/MANUAL_ACTION`。租约到期可恢复 SENDING；仅客户业务确认后 ACKED。

HTTP 成功但业务失败、批次部分接收、响应丢失、字段拒绝及重复发送都有单独场景。客户不支持去重或查询确认时记录限制与双方处理办法，不承诺端到端零重复。

新增可选字段需契约测试证明旧消费者可用；删除、改类型、改单位、改语义、改必填或事件载荷属于兼容性变更。提出新版本、影响清单和过渡方案后再实施，不能在 A 会话中直接修改冻结契约。
