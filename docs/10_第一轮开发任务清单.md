# 慧眼智检第一轮开发任务清单

开发人员执行版 V1.1｜2026年10月10日｜按页面交付与提测

请开发人员按本清单认领页面，交付前端、必要接口、数据迁移、测试数据和验收证据。第一轮建议完成“登录→档案→批准配方→任务→一类设备数据→实时与历史→报警处置”的闭环。**一个页面完成约定范围就提交该页测试，不等待整个模块完工。**

本版承接V1.0任务，保留R01—R12用于能力追踪，实施派工改用G00—G02和Pxx页面工作包。M00—M10继续约束代码和数据边界。全部执行主责是开发人员，可由一人兼任；实际姓名、日期、首接设备及真机范围待负责人确认。

## 一 主责与交付方式

每个页面只指定一名主责开发，负责本页前后端衔接和提测。协作开发按卡片承担具体路径；有第二名开发时交叉复核，一人团队明确“自测，无独立复核”。项目负责人确认范围、业务口径和验收结论，不作为开发执行人。

每页交付必须包含：页面及弹窗、本次必要API与所属表迁移、接口契约、隔离测试数据、实际启动入口、用例及真实浏览器验证、对应模块文档。不能只交截图、静态页或“接口已写完”。

当前只有原型，正式页面均未开始。**现在没有正式页面可提测**；开发完成后在[页面开发与测试台账](12_页面开发与测试台账.md)按UI界面模拟、API真实业务、HW真机分别登记。该台账是当前可测状态的唯一来源。

## 五 页面怎样提测和验收

1. 主责开发自测本页并填写任务卡：版本、URL、账号获取位置、隔离数据、模式、操作和预期、已知问题。UI模拟只证明交互，API模式必须使用真实后端与数据库；MSW和原型回退关闭。
2. 满足本页提测条件后，在第12份将对应模式改为“可提测”。若接口未接、环境打不开或关键依赖未部署，填写“不可测/待条件”及阻塞提供人。
3. 复核开发按本页步骤执行真实浏览器操作，保存输入、预期、实际和证据。无第二名开发时说明无独立复核，不自动填写复核通过。
4. 页面独立通过后登记“该子范围API通过”。设备源仍模拟时HW保持未执行；关联页面尚未完成时联合回归单列，不能提前关闭。
5. 项目负责人或指定验收人确认后冻结明确的行为/路径/契约和提交。模块仍有其他页面或后续能力时，只冻结本次子范围，不冻结整个M04等模块。

所有页检查正常闭环、持久化、权限/数据范围、空态/错误及并发冲突。测量相关页加重复、乱序、断流、换盘、无效/null；报警加恢复与处置分离；真机与客户MES分别留证据。

## 六 第一轮联合验收

R12由统筹开发组织，各页主责开发执行；R12从准备样例开始持续开展，最后核对整条链路。以下全部为待执行。

| 操作 | 必须看到的结果 |
|---|---|
| 新环境部署和登录 | 构建、配置、迁移可复现；无原型身份回退 |
| 规格设备→配方→工单盘号→任务 | 来源与适用正确；创建快照；禁用档案不能用于新任务 |
| 更新配方后执行旧任务、争用设备、重复开始 | 原任务不换版；只有一个占用者；不重复动作 |
| 正常、边界、超限、无效、重复及冲突样本上传 | 按批准样例判定；null不当0；重发不多存；冲突有证据 |
| 检测页→历史→报警→处置复核→总览 | 同一任务/设备/记录；原FAIL保留；汇总与列表一致 |
| 断网与恢复、任务切换、提前结束 | 按设备实际能力补传并对账；不串盘、不伪造覆盖或合格 |
| 批准负载与备份恢复 | 实测达到批准指标；数据及附件关联可恢复；未定指标不能记通过 |
| 功能和材料核对 | 未实现区块标识清楚；源码/契约/迁移/模块文档/逐页证据对应 |

本轮若约定含真机，模拟通过只是阶段结果；不得关闭G02和HW验收。原型既有48项检查不抵扣正式页面或设备验证。
