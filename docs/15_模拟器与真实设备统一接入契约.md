## 2 身份、版本与通用格式

### 2.1 设备身份

使用 `Authorization: Bearer <device_credential>`，凭据由M00受控签发，格式不假定JWT，不在文档、仓库、样例或日志保存真实值。凭据绑定一个factory_id、一个data_environment和明确device_id集合，以及可用操作权限。客户端不能传factory_id改变归属；schema在接入记录中拒绝该字段。

SIMULATED凭据只能上传SIMULATED；REAL凭据只能上传REAL。凭据存在但设备或来源范围不符，整包403且不写任何业务项；过期/撤销返回401。跨工厂对象不返回其详情。禁用设备禁止新会话/心跳/新样本；历史补传是否放行只能通过明确的replay授权，不因禁用就自动销毁本地队列。

首期按测试项目、数据库、附件和凭据隔离模拟数据。测试规则只能用于模拟来源；正式报告和客户MES不能混入模拟数据。设备上传权限不能调用人员账号管理、人工审核、更正或规则批准接口。

### 2.2 版本及HTTP约定

API前缀 `/api/v1`；JSON为UTF-8，字段snake_case；Accept为application/json；JSON写请求Content-Type为application/json。证据上传另用multipart/form-data。生产走HTTPS，本机开发可用回环HTTP；设备凭据不通过URL传递，不向不受信任重定向转发。

请求体的schema_version必须是服务端声明支持的精确字符串，例如1.0。未知版本整包400/SCHEMA_VERSION_UNSUPPORTED。请求id可用X-Request-Id，符合Id格式，否则服务端生成；响应始终回request_id。batch_id只用于追踪，一批重分组可用新batch_id，去重依赖每条稳定来源键。

接入批次不用请求级Idempotency-Key替代逐条去重；会话用client_session_id，绑定确认用ack_id，文件用upload_id。已有人员命令的Idempotency-Key/If-Match约定不改变。

### 2.3 共同字段规则

| 类型 | 规则 |
|---|---|
| Id | 1—128字符，字母/数字开头，后续仅字母、数字、点、下划线、冒号、连字符；大小写敏感，作为不透明标识 |
| 来源原编号 | source_record_id/source_session_id/source_sequence可为厂商字符串，最长128；未知为null，不编造 |
| Sequence | 无符号十进制整数字符串，0—18446744073709551615；不使用JS Number存储或比较 |
| Timestamp | RFC3339，必须有Z或偏移，秒后最多6位小数；不接收无时区时间或闰秒表示；存储不得经毫秒Date截断微秒 |
| Decimal | 十进制字符串，最多14位整数、10位小数；不接受指数、NaN、Infinity、逗号、空字符串或JSON浮点数 |
| null | 明确未知/不适用，不能替换为0、空字符串或上一条数值 |
| 可空字段 | Schema中若列为required，必须出现，未知时显式null；不省略后靠服务端猜值 |
| 未知字段 | 正规业务对象拒绝；版本化raw.data可扩展，但必须满足注册的raw配置及大小限制 |

Decimal是传输上限，不是仪器精度承诺。更高精度需要新契约评估，不静默截断。负数格式可表达原始异常；物理有效范围由方法及能力决定，不能仅因Schema合法就认定有效。

格式依据为 [OpenAPI 3.1.0](https://spec.openapis.org/oas/v3.1.0.html)、[JSON Schema 2020-12](https://json-schema.org/draft/2020-12/json-schema-validation)；HTTP状态及重试语义参考 [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)。它们是接口格式依据，不是三项电缆检测的检验标准。

### 2.4 首期开发限制配置

| 配置 | 开发默认值/结构上限 | 超限行为 |
|---|---|---|
| 测量条数 | 1—500条/批 | 整包413/BATCH_LIMIT_EXCEEDED，不写入 |
| 源报警 | 1—100条/批 | 同上 |
| JSON请求大小 | 1MiB | 413/PAYLOAD_TOO_LARGE |
| raw | 单条64KiB、深度≤8、对象属性≤128 | 逐条REJECTED/RAW_LIMIT_EXCEEDED |
| 回执查询 | 每次1—100个不重复来源键 | 400/REQUEST_INVALID |
| 图像 | 单文件8MiB；PNG/JPEG；metadata≤16KiB；multipart总量≤9MiB | 413或415，不生成AVAILABLE引用 |
| 心跳 | 每10秒；30秒无新鲜心跳判离线 | 是开发配置，不是硬件指标 |
| 心跳最大年龄/时钟容差 | 15秒/5秒 | 过旧或超未来窗口不续在线状态 |

通过GET profile发布实际限制，可更严格；客户端按返回值拆批。容量、上传速度、每日保留量及QPS尚无承诺。Schema上限扩展、降限兼容和真实现场数值要另有版本/配置记录。首版不接收压缩JSON请求体；避免压缩前后大小语义不同。

## 3 接口清单与接入顺序

### 3.1 HTTP操作

下表路径均在/api/v1下；成功返回统一 `{code,message,request_id,data}`。

| 编号与操作 | 所属 | 请求定义→成功响应定义 | 幂等及权限 |
|---|---|---|---|
| I01 GET /ingestion/profile | M04装配M00/M01公开只读结果 | 无体→ProfileResponse，200 | 仅当前凭据的设备及环境；不得枚举全厂凭据 |
| I02 POST /device-sessions | M04 | SessionRequest→SessionResponse，200 | client_session_id；受控设备会话开启权限 |
| I03 GET /devices/{device_id}/assignment | M02，内部使用M01/M03 | 无体→AssignmentResponse，200 | 只读被授权设备当前分配；无分配返回assignment:null |
| I04 POST /devices/{device_id}/assignment-acks | M02 | AssignmentAck→AckResponse，200 | ack_id；同设备绑定确认，不是人员任务start命令 |
| I05 POST /measurements:ingest | M04 | MeasurementBatch→BatchReceipt，200 | factory＋device＋record_id；上传权限 |
| I06 POST /source-alarms:ingest | M04 | AlarmBatch→BatchReceipt，200 | factory＋device＋source_event_id；源报警权限 |
| I07 POST /device-status:heartbeat | M04 | Heartbeat→HeartbeatResponse，200 | 活跃connection_id＋递增heartbeat_sequence |
| I08 POST /receipts:query | M04 | ReceiptQuery→ReceiptQueryResponse，200 | 仅本凭据可访问设备的稳定键，不放开全量历史 |
| I09 POST /evidence | M04 | multipart metadata:EvidenceMetadata＋file→EvidenceResponse，200 | factory＋device＋upload_id；文件上传权限 |

前端查询、下载和管理API仍按第05份，不混入设备接口集。I01/I02/I08是接入技术增量；I03/I04把既有M02快照与端侧确认具体化，不改变模块允许依赖图。I04的连接归属由受控请求上下文提供，M02不反向调用M04或读其表。

### 3.2 正常启动

1. 管理侧准备工厂、设备能力、任务和适用快照，为模拟器或真实适配器分配独立凭据。
2. 客户端读取profile，核对契约版本、身份环境、设备能力、速率策略和限制；不支持时停止上传并报告。
3. 为每个设备打开传输会话，得到connection_id；启动心跳。会话和设备采样会话不是同一概念。
4. 获取任务分配，核对绑定、指标和快照；将已确认快照可靠保存后提交APPLIED确认，失败回REJECTED及原因。
5. 形成稳定记录及本地待发项；批量上传，逐条保存回执；按状态重试或转人工处理。
6. 恢复时先核对既有待发项，保留来源键和原始时间；必要时查询回执，不把重启当作新的采样事实。

缺任务时允许保留测量原文，上传后隔离；不得借用上一盘。源设备只提供快照时明确READ_SNAPSHOT，不能通过高频轮询将相同快照伪装成高频新采样。

## 4 测量数据格式

### 4.1 批次与记录

MeasurementBatch含schema_version、batch_id、sent_at、records。sent_at是此次发送时间，可随重试变化；单条record内部采样事实不得变化。records可以含凭据允许的多个设备或任务；整包权限预检通过后逐条事务处理，不承诺批次原子性。

| 字段组 | 类型与规则 |
|---|---|
| record_id、device_id | 必填Id；record_id在首次可靠记录时分配，重发不变 |
| capture_session_id、capture_sequence | 必填采集程序会话及单调本地序号；区分适配器实际捕获顺序，不冒充设备原序号 |
| source_record_id、source_session_id、source_sequence | 必填可空，保存厂商原身份；适配器新增身份不能塞进这些字段 |
| sample_kind | NEW_SAMPLE或READ_SNAPSHOT，必须符合设备能力及真实新样本证据 |
| task_id、binding_id、binding_version | 必填可空；无法核实绑定时隔离，不能用当前任务覆盖历史 |
| sample_time、time_source | 采样或捕获时刻；DEVICE/ADAPTER/SIMULATOR；REAL不接受SIMULATOR时间来源 |
| position_m、position_quality、position_segment_id | KNOWN时有米数及区段；UNKNOWN/INVALID时position_m为null；复位/倒退另开段，不跨段累计覆盖 |
| source_type、data_environment | 设备接入仅DEVICE或DERIVED；REAL或SIMULATED；MANUAL/IMPORT走独立补录接口 |
| data_status | VALID/INVALID/MISSING，和唯一目标value状态一致；STALE只作为查询新鲜度或raw中的来源原因 |
| recipe_version_id | 必填可空；有正式规则则引用任务冻结版本，不能临时选择“最新配方” |
| values | 恰好一个目标指标；保留数组形态但本期不接收一条记录多业务指标 |
| raw | `{schema_version,data}`，带版本原始/辅助数据，注册的原文配置决定允许字段 |
| evidence_refs | 0—16个已登记证据Id，不接受任意URL；无图像为空数组 |

capture_session_id在本地持久状态丢失或开启新的采集周期时重新生成；同一会话内capture_sequence严格递增，测量与报警共享序号空间。重发保持原值。source_sequence可回绕或重置，按设备原会话解释。不同合法样本即使时间、位置、数值相同也不能去重为一条。

### 4.2 单指标value

| metric_code | unit | 值解释 |
|---|---|---|
| SHIELD_OVERLAP_RATE | % | "12.5"表示12.5%，不是0.125；原宽度与节距放raw |
| WIRE_GAP | mm | 必须关联明确局部/平均/最大方法与窗口，不能自行四点平均 |
| OVALITY | % | 不圆度指标；X/Y外径仅辅助，不自动构成全周不圆度 |

Value包含value、data_status、source_quality_result、method_id、window、reason_code。VALID要求非空Decimal；INVALID/MISSING要求value:null、source_quality_result:NOT_EVALUATED及非空reason_code，有异常原值放raw保留。方法未批准但指标本身有效时保留value，平台不判定，不清空合法测量。

source_quality_result只保存来源判断，不直接成为平台quality_result。真实环境的值、单位、方法、配方及窗口一致且方法批准后才可作平台判定。模拟环境可以使用显式TEST_ONLY测试规则，结果仍是模拟来源，不能进入正式报告。

Window字段均出现：kind、definition_id、start、end、position_from_m、position_to_m。INSTANT时除kind外全null；TIME时start/end有值且end≥start，位置为空；POSITION时位置两端有值且to≥from，时间为空；DEVICE_DEFINED必须有definition_id，其余按注册方法定义。非瞬时窗口也要绑定相应definition_id，禁止用一个无版本的“平均值”混合统计。

### 4.3 三项原文配置

首版提供模拟配置标识wire-gap-sim.v1、diameter-aux-sim.v1、alarm-sim.v1供样例使用，必须与SIMULATED凭据能力匹配；真实配置须根据供应方报文另登记。原始局部间隙数组、搭盖宽度/节距、X/Y外径保留单位、有效性及方法/算法版本，不在本契约编造厂商字段。

raw.data最多128个属性、深度8、编码后64KiB；数字测量和超过安全整数范围的值用字符串。未知raw版本逐条拒绝RAW_SCHEMA_UNSUPPORTED；配置已注册但无法识别业务方法时可保留原文且隔离/不判定，不能猜公式。

完整结构样例见 [正常间隙](../../contracts/devices/v1/examples/01-measurements.json)、[只有辅助外径的不圆度缺测](../../contracts/devices/v1/examples/02-ovality-missing.json)。样例ID为占位，需先建立匹配夹具；不能拿JSON结构通过宣称接口落库成功。

### 4.4 必须另做的语义校验

| 编号 | 跨字段或状态约束 |
|---|---|
| S01 | 整体data_status等于values[0].data_status；指标/单位匹配设备能力及任务 |
| S02 | 绑定三元组、task_id和配方符合M02历史快照；不可关联则隔离 |
| S03 | 来源环境、设备、工厂、时间来源符合凭据；禁止跨范围 |
| S04 | Sequence不超过uint64；同capture_session内稳定键与序号对应，不因重发变化 |
| S05 | 有可靠新样本标识才NEW_SAMPLE；快照不增加未经批准的覆盖/采样次数 |
| S06 | Window按4.2组合，数值范围和单位换算遵循方法版本，不静默换算 |
| S07 | 时间与位置关联历史区段；异常时钟/未来采样标记隔离，不改写原时间 |
| S08 | evidence属于同设备/环境/来源键，文件可用；无图像不能补演示图片 |
| S09 | source_quality_result不越权决定平台判定；批准状态及模拟标识贯穿事件 |
| S10 | raw注册版本、深度、大小、安全数字、脱敏及能力一致 |
| S11 | 回执数量、input_index、source_id、计数及状态字段相互一致 |
| S12 | 会话、绑定确认、心跳顺序和文件重试遵守第6节状态规则 |

## 5 接收回执与幂等

### 5.1 固定处理次序

1. 检查身份、媒体类型、字节数、JSON语法、重复属性名、包络版本/字段和批量数量。失败返回整包错误，尚未写入。
2. 对可解析device_id及环境做整包权限预检；任一越权或来源伪装返回403/NONE，不返回其他项目的成功结果。
3. 保留原输入顺序，逐条校验Schema，再校验S规则并分别提交事务。单项格式错误也返回该项REJECTED；包络合法时不能让通用全体Schema校验提前把整包变成400。
4. 每条记录、必要资格/判定及所属outbox同事务；持久化确定后产生回执。处理故障若结果未知则整包500/503、write_outcome:UNKNOWN，已确定提交项不会回滚成“未接收”。

OpenAPI描述的是全部项目合法的请求形状；反例表示单条格式不合法，运行入口须按上述两阶段校验实现。records为非数组、空数组、根对象未知字段是整包错误；数组内非对象或缺record_id是逐项错误，回执source_id:null、input_index仍可定位。

### 5.2 逐条回执

BatchReceipt中data含schema_version、batch_id、counts及items。input_index从0起，与原数组逐一对应，items数量等于请求数量且顺序不变。source_id对应record_id或source_event_id；stored_id是平台内部引用，不能将来源键当作内部ID。

| receipt_status | 持久化与字段 | 客户端动作 |
|---|---|---|
| STORED | stored_id、first_received_at非空，initial_status为STORED；error_code为空 | 标记已送达，按保留策略留本地原文 |
| DUPLICATE | 同键同内容；返回原stored_id、初次接收时间及原initial_status | 视为已送达；原先隔离仍是隔离，不自动算正式生效 |
| QUARANTINED | 原文已持久化；initial_status为QUARANTINED，error_code说明绑定/时钟等原因 | 停止自动重发，转待处理；不进入正式统计 |
| REJECTED | stored_id/initial_status/first_received_at为空，error_code必填 | 确定该项未存入业务记录；仅retryable:true可自动重试 |

非拒绝项retryable:false、retry_after_ms:null；原隔离记录重复上传时保留原隔离原因。REJECTED可以有受限诊断证据，但不能声称产生了业务测量。回执不返回“整盘合格”，也不承诺报警消费者、报告或MES已经完成。

counts四种状态相加等于total，total等于items数。同一批次重复键按输入顺序处理：第一条决定首次存储，后续同内容DUPLICATE、异内容REJECTED/RECORD_PAYLOAD_CONFLICT；并发请求也必须由唯一约束保证只有一个首次记录。合法批次即使全部拒绝也返回200及完整逐条回执，客户端不能只看HTTP状态。

### 5.3 稳定键与规范化内容

测量去重键为凭据解析的factory_id＋device_id＋record_id；报警为factory_id＋device_id＋source_event_id。data_environment由注册设备和凭据约束，不允许将同设备身份跨环境复用。数据库保留原文与规范化摘要。

内容规范化标识为ingest-c14n.v1：对记录中声明的Decimal字段去无意义末尾0，负零归0；Timestamp字段转换UTC并保留到微秒精度，去末尾小数0；evidence_refs作为集合按Id排序；其余数组保持原顺序。raw.data保留字符串原样，不擅自把其中"1.0"变成"1"；厂商原格式变化可以形成冲突。

然后按 [JCS RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)确定性序列化，以UTF-8计算SHA-256。不能直接用任意JSON.stringify的属性插入顺序。拒绝重复属性、非有限数字、非法Unicode代理项；不做Unicode归一化。Decimal规范化在JCS之前，不能依靠浮点解析实现。

哈希输入包含全部单条记录字段及raw；不包含批次batch_id/sent_at、HTTP追踪号、服务器received_at或连接重建信息。补传保留原捕获会话和序号。绑定修正、证据后补及人工更正走追加关联/修订，不通过修改旧record_id的payload完成。

本版未设置自动去重清理。记录及其稳定键/摘要保留期间，重复语义必须成立；未来归档要携带去重索引，若批准关闭旧会话重放范围，则拒绝其再次写入并转人工，不能删除索引后把旧数据当新记录。具体保留天数及磁盘预算由T06确定，不承诺无限存储。

### 5.4 查询与结果未知

I08按设备、kind和source_ids查询初次接收结果，逐个返回FOUND或NOT_FOUND及原stored_id/initial_status/first_received_at。FOUND不等于当前资格EFFECTIVE；后续资格变化由人员查询接口查看。NOT_FOUND只表示该查询快照未查到，不证明没有正在提交的请求。

丢失响应时，客户端可以先查回执或直接原键重发；不得更换记录ID“解决”未知状态。服务端不能用没有落盘的内存响应宣称成功。伪造、不完整或不匹配回执时客户端将相关项视为UNKNOWN，保留队列并对账。

## 6 其他接口和状态规则

### 6.1 传输会话及心跳

I02请求含device_id、data_environment、client_session_id、producer_version。M04原子建立connection_id；同设备同client_session_id重试返回原活跃连接，新client_session_id建立连接时撤销旧连接的心跳/当前绑定确认资格。已被替代的旧client_session_id再开户返回409/SESSION_SUPERSEDED，不复活旧连接。新建会话必须限流并审计替代行为，多个生产者不能无声抢占。

connection_id仅用于连接新鲜度及当前绑定确认，不是补传记录的身份。已授权原始测量和报警可在新连接下补传旧capture_session数据；不因重启连接就重写样本ID。

I07包含connection_id、递增heartbeat_sequence、sent_at、capture_session_id、observed_task_id/observed_binding_id、last_sample_time/last_record_id、queue_depth、disk_free_bytes、instrument_state和config_version。设备只上报观察事实，不能发送online:true替代判断。

服务端以当前连接、源时间窗口及递增序号接收心跳：过旧、重复/倒序不延长在线，200 accepted:false并给HEARTBEAT_EXPIRED或HEARTBEAT_OUT_OF_ORDER；旧连接409/SESSION_SUPERSEDED。首次合法新心跳返回accepted:true及server_time、online_until；其他情况online_until:null。future时间超过容差同样accepted:false/CLOCK_SKEW；客户端根据server_time诊断时钟，不改历史采样时间。

心跳不进离线重放队列，失败后发送当前新心跳；旧心跳不补传。业务数据最后接收时间不能更新心跳新鲜度，补传旧记录不伪造设备当前在线。instrument_state:DISCONNECTED与适配器在线可同时存在。

### 6.2 任务绑定和快照确认

I03返回当前assignment或null。Assignment含binding_id/binding_version、task_id/task_version/state、factory/spool/process/specification内部ID、metric/unit、recipe_version_id、snapshot_hash、evaluation_policy及rule_snapshot。绑定版本用Sequence字符串；快照是指定版本，不查询“最新规则”替代。任务结束或配方更新不覆盖历史绑定。

rule_snapshot中的APPROVED、TEST_ONLY、UNAPPROVED分别代表批准、模拟专用和未批准。VALIDATE_ONLY仅接收/校验、不形成平台PASS/FAIL；EVALUATE_APPROVED仅在方法与规则批准（模拟可TEST_ONLY）时执行。实际方法算法及parameters由M03方法版本定义，不支持任意脚本。comparison为null时不作阈值比较；GE仅lower非空、LE仅upper非空、BETWEEN两端非空且lower≤upper，均含边界。规则及comparison必须与指定方法匹配。快照hash以整个Assignment对象（除snapshot_hash自身）为输入，按同版本规范化；样例中的连续a摘要只是占位，不能作为正确摘要测试向量。

I04请求包含ack_id、connection_id、binding三元组、snapshot_hash、result、effective_at、capture_session_id、first_capture_sequence、reason_code。APPLIED必须有生效时间及首个本地序号；REJECTED必须有原因且生效边界为空。受控HTTP装配入口核验M04连接资格后向M02传可信上下文，不由M02直接读取M04表或新增反向业务依赖。连接资格以入口检验时刻为准，替代后新到的旧连接请求拒绝；已通过入口的在途请求仍受M02绑定版本约束，不撤销已持久化历史确认。服务端验证当时授权和快照后持久化，重试ack_id同内容返回duplicate:true，异内容409。

APPLIED只表示采集程序已应用数据关联快照，不证明机器执行了物理动作，也不替代人员start权限。记录按capture_session/sequence边界关联；切盘确认前产生的新记录隔离，不猜新任务；同任务不同绑定版本不可无痕混用。设备重启后可以重新确认同一绑定的新capture_session；旧会话区间保留。

断网期间缓存已应用任务可继续按批准离线策略记录；未知新任务不自行创建。确认响应丢失先原ack_id重试；晚到的原确认若已持久化返回原结果，尚未记录且已被新绑定替代则409/BINDING_SUPERSEDED，记录保留待关联。旧任务迟到测量依据历史绑定和采样范围接收，不按当前RUNNING任务筛掉全部历史。

暂停/恢复、异常结束、离线自主换盘及现场人员确认策略仍待T10，不能由本契约假设允许。需要这些能力时细化M02/M09工作包，不删去原始待处理数据。

### 6.3 源报警

I06使用AlarmBatch。source_event_id标识一次事件，source_alarm_key标识一个生命周期；event_kind为TRIGGERED/RECOVERED/ACKNOWLEDGED。severity统一INFO/WARNING/ERROR/CRITICAL，厂商等级保留raw并有映射记录。源ACK不等于平台质检复核。

无测量的设备故障允许task_id、binding_id、record_id为空，不伪造测量。报警source record_id引用的是同设备稳定来源键；尚未收到相应测量时保存待关联，不凭空建测量表。无法核实非空任务绑定时隔离。先收到RECOVERED时保留原事件并等待触发上下文，不能以接收顺序制造虚假恢复；跨设备原会话缺可靠顺序时显示待核实。

### 6.4 证据上传与后补

I09的metadata部分使用application/json，file为二进制PNG/JPEG。metadata含upload_id、device/environment、source_record_key、captured_at、content_type、byte_size、sha256、evidence_kind。文件名不构成存储路径；校验真实类型、字节数与摘要，不信任声明。

上传先暂存校验，再可靠保存文件和元数据；全部可读后才返回AVAILABLE及evidence_id。upload_id同内容重试返回原引用，异内容409/EVIDENCE_PAYLOAD_CONFLICT。文件已写但事务失败时不得返回成功，恢复流程清理或对账；中断客户端可按同upload_id重新上传，不以回包丢失创建新文件。

source_record_key允许测量先到或证据先到；由M04同设备范围的追加关联对账，不修改已经哈希的测量payload。原evidence_refs可以为空，后补文件以关联版本展示；已发布报告仍保留其原快照及缺证据状态。文件存在但来源不匹配不得关联；缺相机能力允许一直无图像，不生成假证据。

## 7 异常处理、重试和本地队列

### 7.1 整包异常

所有平台JSON错误包含code、message、request_id、data:null、write_outcome、retryable、retry_after_ms、field_errors。field_errors.path使用JSON Pointer，例如/records/2/values/0/unit。代理层HTML错误或网络异常没有这些字段时按UNKNOWN处理。

| HTTP/错误 | write_outcome | 重试动作 |
|---|---|---|
| 400 REQUEST_INVALID / SCHEMA_VERSION_UNSUPPORTED | NONE | 修格式或升级配置，原样重试无意义 |
| 401 AUTH_REQUIRED / AUTH_EXPIRED | NONE | 暂停发送、更新凭据；不删队列；响应含WWW-Authenticate |
| 403 ACCESS_DENIED / SOURCE_NOT_ALLOWED | NONE | 检查设备/环境授权，禁止自动改标REAL |
| 404 RESOURCE_NOT_FOUND | NONE | 核实被授权对象；不泄露范围外资源 |
| 409 SESSION_SUPERSEDED / BINDING_SUPERSEDED / ACK_PAYLOAD_CONFLICT / EVIDENCE_PAYLOAD_CONFLICT | NONE | 连接/绑定重新核实；内容冲突转人工 |
| 413 PAYLOAD_TOO_LARGE / BATCH_LIMIT_EXCEEDED | NONE | 拆批后仍使用原逐条键；单条超大需修源协议 |
| 415 MEDIA_TYPE_UNSUPPORTED | NONE | 改合法媒体类型，不重发原内容 |
| 422 SNAPSHOT_HASH_MISMATCH / BINDING_INVALID | NONE | 重新获取核对快照；不猜版本 |
| 429 RATE_LIMITED | NONE | 服从Retry-After秒数，再作带抖动退避 |
| 500 INTERNAL_ERROR / 503 DEPENDENCY_UNAVAILABLE | UNKNOWN，只有确定未进入写入时才能NONE | 原键查询或重试，不清队列、不换ID |

500/503不是全批回滚保证。代理超时、客户端超时和断连接同样可能已经落库。服务端响应中不得泄露SQL、连接串、凭据或堆栈。

### 7.2 逐条异常

| 原因 | 逐条状态/错误码 | 自动重试 |
|---|---|---|
| 字段格式/单位/窗口不合法 | REJECTED / RECORD_INVALID、UNIT_MISMATCH、WINDOW_INVALID | 否 |
| raw未知或超限 | REJECTED / RAW_SCHEMA_UNSUPPORTED、RAW_LIMIT_EXCEEDED | 否 |
| 同键异内容 | REJECTED / RECORD_PAYLOAD_CONFLICT | 否，保留冲突，不覆盖 |
| 有格式合法原文但绑定不明 | QUARANTINED / TASK_BINDING_UNVERIFIED | 否，转关联处理 |
| 原时间异常且无法核实 | QUARANTINED / SAMPLE_TIME_UNVERIFIED | 否，保留原时间 |
| 证据引用不存在/不匹配 | REJECTED / EVIDENCE_NOT_READY、EVIDENCE_SCOPE_MISMATCH | 前者上传或对账后重试；后者人工处理 |
| 可确定事务未提交的短暂依赖故障 | REJECTED / DEPENDENCY_UNAVAILABLE | 是，按retry_after_ms |
| 暂无批准方法但有合法原值及绑定 | STORED；平台NOT_EVALUATED | 不重发，不把方法缺失当接收失败 |

REJECTED且retryable:false不等于可以删除本地原文。修正尚未存储的格式可按记录恢复流程重新提交；已存储原键绝不可改内容，正式更正另走人员修订接口。客户端无需解析中文message判断策略。

### 7.3 队列和节流

本地原文与待发项同事务。状态建议PENDING→SENDING→STORED/QUARANTINED/REJECTED；超时或进程终止的SENDING租约过期回PENDING。DUPLICATE按其initial_status终结本次投递，不凭它把原隔离数据升级。重试是至少一次交付，服务端幂等防止重复业务效果。

建议开发退避为1、2、4、8…最多60秒并加0—20%抖动；服务端Retry-After或retry_after_ms为等待下限。每设备先限制一个未完成批次，后续按压测加并发。频率及并发不得从图表刷新率推导。连续失败进入可见告警，恢复后限速排空积压；队列接近容量阈值时预警，已满时不静默丢弃后仍声称可靠采集。

source_key、摘要、尝试时间、request_id、逐条状态和失败原因用于对账。日志脱敏，不记录Bearer。模拟器保存run_id、随机种子、场景版本、原样本清单及回执；新运行用新来源键空间，恢复同一运行沿用旧键。

以下32项运行用例当前全部未执行。Schema静态正反例通过仅证明格式，不抵扣权限、事务、幂等、页面或真机验收。
