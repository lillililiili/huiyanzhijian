## BR01 身份与适用性

工厂→产线/工序→设备；工单→盘/线芯→检测任务→测量。一个任务只有一个 metric_code，三项只在实际适用工序执行，同盘可以有多任务和多台同类设备。详情必须使用内部 ID；只给显示盘号且存在多个候选时要求选择工厂/工单，不能默取第一条。

规格保存电压、芯数、截面积、结构及工序适用关系；设备保存已核实能力。35–220kV 是业务边界，不等于一台设备覆盖所有外径/材质。原型只有35/66/110/220及铜带/铜丝两类选项，正式目录和复合屏蔽适用关系由 T04 确认。

同设备同一时刻最多一项 RUNNING/PAUSED；同盘同工序同线芯同项目是否允许多设备并行复测由 T10 确认，不能照搬原型只按“盘号+项目”禁止重复。幂等创建与业务重复不是一个规则。

## BR02 任务与冻结时间

原型 pending/running/completed 映射为 CREATED/RUNNING/ENDED；页面“已分配”只是有设备/规则绑定，不新增 ASSIGNED 业务状态。

| 原状态→命令→新状态 | 前置条件与副作用 | 原型/正式差异 |
|---|---|---|
| 无→create→CREATED | 已存在生产身份、启用规格、相容设备、指定批准配方、计划长度>0；创建时冻结上下文与规则 | 原型在创建时冻结，修正旧文档“开始时保存”歧义 |
| CREATED→start→RUNNING | 复核绑定、规则资格和设备就绪；事务抢占设备；记录开始时间/操作者/任务版本 | 不静默改用新配方；设备失联时返回未就绪 |
| RUNNING→pause→PAUSED | 若 T10 采纳，保留设备占用，记录原因、采样边界与端侧确认 | 原型未实现；暂停不等于停机/PLC命令 |
| PAUSED→resume→RUNNING | T10 采纳后复核同一盘/设备/规则；记录新采集区段 | 不把暂停期算有效连续覆盖 |
| RUNNING/PAUSED→end→ENDED | 记录实际停止边界、原因和覆盖状态；端侧确认方式待协议决定 | 原型有一条记录即可结束；正式允许提前/异常结束的条件待 T10 |
| ENDED→start | 拒绝；重检创建新任务关联原任务 | 补录不重新打开原任务 |

取消待开始任务、无样本结束、失联强制结束是待 T10 决策的异常路径，不能用删除或伪造样本绕过。命令状态与物理设备状态分离：平台收到请求不等于设备已切盘，M09 需回传实际生效版本/时间；确认前不把新数据默认绑给新盘。所有状态转换具幂等、乐观锁、操作日志。

## BR03 原始数据、有效性、正式资格

| 维度 | 正式含义 | 原型映射与限制 |
|---|---|---|
| 来源方式 | DEVICE / DERIVED / IMPORT / MANUAL | 不能把“人工导入补录”混成无法区分的来源 |
| 环境 | REAL / SIMULATED，由接入身份和部署环境验证 | 原型包括“自动采集”在内全部 SIMULATED |
| 指标有效性 | VALID / INVALID / MISSING，源当时陈旧可留原因 | 原型 valid/invalid 合并了缺失等情况；缺值为null，不补0 |
| 查询新鲜度 | FRESH / STALE / MISSING，相对查询时点 | 不因时间经过改写历史VALID记录；设备在线也可无新鲜数据 |
| 判定 | PASS / FAIL / NOT_EVALUATED | 原型 invalid 映射为无效/未判定，不能变PASS |
| 接收 | STORED / QUARANTINED / REJECTED；DUPLICATE是回执 | 已接收不等于已审核、质量合格或MES确认 |
| 使用资格 | PENDING_REVIEW / EFFECTIVE / REJECTED / VOIDED / SUPERSEDED | 原型无审核/作废版本；正式查询显式筛选 |

有合法数值而方法未批准：保留数值且 NOT_EVALUATED。仅有 X/Y 外径时不圆度为 MISSING，不把辅助量有效性提升成目标指标有效。原始载荷、资格修订、判定版本、来源证明分别保留。正式报告禁止 SIMULATED；模拟环境可以生成带演示标识的报告用于评审。

## BR04 测量方法与阈值

| 指标 | 原型事实 | 正式契约必须确定 |
|---|---|---|
| 搭盖率 | 值对照≥10%；宽度/节距由演示数值生成 | 厂商实际量测字段、分母/窗口、方向、阈值及等号、图像可用性 |
| 铜丝间隙 | 四处局部间隙平均值≤3mm | 局部/平均/最大哪个判定、测点数量/遮挡/无效点策略、全周能力 |
| 不圆度 | 设备输出≤8%，X/Y只是辅助演示 | 共久真实输出是否包含不圆度；若仅外径则由批准方法计算，方向与统计范围明确 |

10%/3mm/8%及等号仅为演示，T04批准后才能用于正式判定。显示舍入不影响完整精度判定；新配方只对明确选择它的新任务生效。原型每项只有一套全局启用规则；正式规则按工厂/规格/工序/方法/版本选择，不能为修改一个规格禁用其他规格配方。

配方建议状态 DRAFT→APPROVED→RETIRED：草稿可编辑；批准内容不可改；退休禁止新任务选用。已有 CREATED 任务使用被退休配方时暂停开始并提示重新设计/确认，不静默换版；已有 RUNNING 任务继续原快照，紧急撤销另经变更流程。规则维护和批准权限分离，人员安排由项目负责人确定。

## BR05 时间、位置与覆盖

存储 UTC 时间点，接口含偏移；保留设备原时区/时钟来源、采集时间、服务端接收时间、真实操作时间。原型无偏移的演示时间字符串不作为生产格式。工厂时区决定“今日”；本机/浏览器时区不得改变业务日期。

位置包含米数、质量、区段 ID、任务/线芯/工序。null 为未知；换盘、倒退或复位建立新段或显式异常，禁止把不同工序相同米数直接拼成同一物理点。

累计计米进度=批准计米口径下完成位置/计划长度，仅供进度展示；有效覆盖=批准采样间距和连续性规则下的区间并集。数据中断不能按两端连线算覆盖。缺少位置/频率证据时 coverage=UNKNOWN，显示“覆盖待核实”，不能算100%。T04/T06/T10确认计米与覆盖规则后建立黄金样本。

## BR06 统计与查询口径

1. 列表、卡片、曲线、导出共用过滤条件、权限范围、sample窗口和received截止点；只改变页码不改变统计分母。
2. “今日任务”建议按工厂当日创建任务计数，运行中任务另列且可含跨日任务；如客户要求按开始日期则 T13 明确。原型全量任务数不能迁用。标题须注明统计口径。
3. `total` 为范围内原始记录数；`effective` 为正式有效资格数；`valid` 为 effective 集合中的有效指标数；`evaluated=pass+fail` 也仅在 effective 集合中计算。`not_evaluated`、`invalid/missing`、`quarantined`、`pending_review`、`voided`分别列出并标明维度，分类维度不可简单相加冒充 total。资格先选最新修订，作废/被替代后不能回退取旧的 EFFECTIVE 版本。
4. 记录符合阈值比例 `pass/evaluated`，分母0显示“—/无可判定记录”；不是整盘合格率。报警数按报警ID，超限数按记录ID/判定版本，不能把两者强求相等。
5. 均值/极值按指标、单位、方法/统计窗口、工序分组；跨规则汇总时提供分组和权重，默认不展示混合均值。跨项目可展示记录数量，但数量汇总不形成整体产品质量结论。
6. 当前读数展示选定设备和任务的最新样本及时间，包括最新无效状态；不能跳过无效值冒充当前正常。前一个任务的数据标为历史，不显示成新任务实时值。
7. MES 比例必须指定接收端、消息类型与版本：分子业务ACKED，分母满足约定推送资格的记录，给出待发/重试/拒绝/无需推送数。不能把未配置或无数据显示为100%。原型当前窗口确认比例只是演示。
8. 趋势点、抽屉、图像、报警共用 record_id 与判定版本。降采样注明方法并保留异常可定位，原始导出使用完整过滤结果。

## BR07 报警生命周期与人工处置

`lifecycle=ACTIVE/RECOVERED` 描述数值/设备状态；acknowledged 描述已阅；`handling_state` 描述人工工作，三者独立。

| 状态/动作 | 目标与约束 | 下游 |
|---|---|---|
| 新异常 | PENDING；记录源、设备、任务、规则、记录、触发时间 | 首页待办/报警列表 |
| acknowledge | 只追加确认人/时间，不自动改变处置或原值 | 时间线 |
| PENDING→handle | PROCESSING；必填原因/行动意见 | 列表与详情同步 |
| PROCESSING→submit | HANDLED；提交处理结论/依据 | 等待授权质检复核 |
| HANDLED→review通过 | REVIEWED；服务端实际复核人和时间 | 报告条件重新检查 |
| HANDLED→review驳回 | PROCESSING；记录驳回原因 | 回到处理待办 |
| REVIEWED→补充意见 | 追加，不覆盖旧意见；重新打开需独立授权和理由 | 提示相关报告资料已变化 |

原型 resolved 仅代表其合并流程完成，不能自动迁移为正式 REVIEWED。原型必须数值恢复才能 resolved，正式停止/报废/无后续样本时能否以人工核实结束待 T12；不可伪造恢复样本或时间。连续超限合并、防抖、源报警与平台重复关联、陈旧/离线故障的触发与恢复另按批准策略版本执行。处置人由认证会话确定，手填名称不构成责任签名。

## BR08 导入、手填、审核和更正

原型已有模板→预览→保存有效行，支持历史任务补录；没有批次审核、撤销与更正闭环。正式建议流程：

`原文件/手填 + 原因 → 按模板校验 → 逐行存储(PENDING_REVIEW) → 质检审核 → EFFECTIVE → 报警/统计/报告/MES消费`

保留文件摘要/物理行号/模板版本/操作者/原始输入。检查内部任务身份、指标、单位、时区、采样时段、位置质量、数据环境、稳定来源键和历史规则。预览时检查通过、提交时仍须重验；越界/重复/失效分别逐行返回。晚上传但采样在任务内是迟到；采样时间本身在任务外则隔离或退回，不凭当前任务自动吸收。

去重使用稳定源记录键；没有源键时约定源文件摘要+行号等身份策略。同任务+时间+米数只能标疑似重复，不能作为唯一硬去重（可能存在不同合法采样）。跨文件重传确认机制待 T11。保存与审核分开，默认建议录入人与复核人不同；如团队需兼任须明确批准，不由前端任意选人。

正式审核后才生成超限待办与MES资格；“无效数据已入库”也不能变合格。更正写替代记录，原记录SUPERSEDED；撤销资格为VOIDED，历史不删。相关报警加注来源已更正，旧报告标数据已变化并可重出新版，已发送MES按客户更正契约处理。普通重试不覆盖旧发送内容。旧任务结束不阻止合规迟到，但已发布报告不自动更新。

## BR09 报告、模板与放行边界

| 报告类别 | 范围与最低前提 | 不能推断 |
|---|---|---|
| STAGE | 已有记录、明确任务/采样窗口/接收截止；运行中也可生成 | 最终检测完成或产品放行 |
| TASK_FINAL | 一项ENDED任务；有效数据；资格/方法/覆盖明确；关联事件处理水位齐；相关质量事件已复核 | 无效或缺测自动合格 |
| SPOOL_SUMMARY | 同盘明确任务/线芯/工序集合；列出适用、未检测、不适用；上述逐任务条件和缺口说明 | 所有盘默认都有三项检测 |

正式建议：允许记录已确认缺测的最终过程报告，但必须醒目显示覆盖不足，不给放行结论；是否阻断最终报告由 T09/T10 批准。未核实覆盖、方法未批准、审核未结束、事件积压时可出阶段/问题记录，不能发布正式最终报告。

质量报告状态：DRAFT→GENERATED或FAILED；GENERATED→PUBLISHED。生成后输入/统计/模板/精度/时区快照冻结；修改模板或显示精度不重绘旧发布内容。失败重试不产生重复版本；重出指向 supersedes_report_id。数据截止同时限制采样时间和平台接收时间，并固定判定/资格版本。物理文件及输入清单有摘要，下载鉴权；大数据异步生成，不无限塞入JSON。

原型的“预览阶段报告”实际创建快照并记审计，正式按钮要明确区分只读预览和创建报告。原型最终报告不等于批准发布，浏览器打印不证明正式PDF生成/归档服务已完成。模板不能通过隐藏异常或演示声明改变报告事实；是否允许隐藏明细仅影响排版，不删除快照证据。模板签审栏是文本，不是有效电子签章。

## BR10 MES 与设备离线

平台接收成功、MES发送HTTP成功、MES业务确认分别记载。M07按业务键+版本幂等，租约/重试/拒绝/人工处置分开；逐次尝试可查。响应丢失先按协议查询/幂等重发；客户无此能力时列入真实限制。MES故障不改测量判定、任务状态或报警处置。

M09先落本地测量及上传队列，再上传；设备报警触发/恢复事件也逐条持久化。缺任务/规则时不借用上一盘。平台断网不应阻止已具备条件的现场检测；源仪表离线则停止产生新有效样本并显示缺测。模拟“场景恢复”不删除历史失败/无效记录。真实恢复必须对账稳定键、数量、区间和证据。

## BR12 统一异常与恢复

加载/空数据/不适用/未检测分别显示；设备离线显示最后时间并标历史；局部查询失败只标相应区块。无权限不给敏感详情，可返回统一404；提交中禁重复按钮但服务端仍幂等。版本过期保留用户输入，刷新差异后重新提交。证据缺失/到期显示原因，不能补演示图。批量部分成功保留原行号/记录键和可重试集合。

规则未批准、设备能力缺项、事件投影积压、覆盖未知均是可恢复业务状态；显示负责人和入口。生产系统不包含演示数据重置和伪造故障恢复按钮。正式诊断只验证明确授权范围，不因配置页有按钮就自动发送外部请求。

## BR13 AI与测量责任

产品1/2算法来自ODM约定结果；平台保留算法/方法版本和实际开放证据，不自行补相机能力。M09只按批准方法处理共久真实输出。不圆度双向数据不等于360°重建。无大模型自动改阈值、自动判产品放行或代签功能。AI生成素材只作原型图；实际判定是批准测量规则的执行，人工复核针对质量处置，不要求每条自动量测都手工审批。
