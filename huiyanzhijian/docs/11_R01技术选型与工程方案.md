## 一 为什么适合现有项目

原型有27个页面入口，主要是档案表单、任务操作、曲线、历史查询和报警处置。原生HTML/CSS/JavaScript适合确认交互，正式阶段需要复用表单校验、明确接口类型、持久化和服务端权限，因此推荐Vue组件化迁移。保留页面结构、色彩、已有资源和ECharts图表配置；按页改造成Vue组件，不要求重新设计全部界面。

原型的localStorage、任意密码、手工在线、采集下一条、模拟MES回执不能作为正式实现。迁移时以第07份页面映射、第08份正式规则差异为依据，避免把原型简化带入后端。

| 选择 | 对本项目的作用 | 取舍 |
|---|---|---|
| Java与Spring Boot | 管理任务事务、身份权限、审计、版本、接收和定时重试 | 前后端两种语言，但职责明确，适合长期维护的工厂业务平台 |
| Vue与TypeScript | 表格表单组件、路由、页面状态及接口类型检查 | 不直接复制原型全局可变状态；需要逐页迁移 |
| Element Plus | 统一表格、表单、弹窗、分页与反馈 | 调整主题适配原型，不以组件库默认外观替代原图 |
| PostgreSQL与MyBatis | 事务、唯一约束、明确SQL及测量时间查询；复杂筛选可解释 | MyBatis是SQL映射工具，不依赖自动建表；迁移独立管理 |
| ECharts 6.0.0 | 延续原型曲线、阈值线和交互 | 先保留原版本，升级另行验证图表行为 |
| 模块化单体 | 同一进程内通过公开接口调用，单机也能部署 | M00—M10不是11套服务或11个人；规模有证据后再拆服务 |

Vue官方支持TypeScript，推荐create-vue与Vite；Vite构建本身不代替类型检查，需要单独运行vue-tsc。[Vue TypeScript说明](https://vuejs.org/guide/typescript/overview)。Element Plus面向Vue 3和现代浏览器，首轮验收浏览器建议为现场使用的Chrome或Edge，版本由G00记录。[Element Plus安装说明](https://element-plus.org/en-US/guide/installation.html)。

备选方案：全TypeScript后端可减少语言切换，但目前没有团队只熟悉JavaScript的证据；C#/.NET适合团队已有C#资产或厂商仅供.NET SDK的情况。目前均不作为平台首选。如果设备SDK限制语言，只调整独立采集适配器，不因此重写平台。数据库若客户强制MySQL，应在初始化前重新核对SQL与迁移，不同时维护两套数据库实现。

每页指定一名**主责开发人员**，负责协调该页前端、必要接口、所属表迁移、测试数据及浏览器验证。可由一人全部完成，也可由其他开发协作；不再把“前端做完、后端未接”计为页面业务提测完成。

一个A会话实现一个页面工作包，允许修改任务卡明确列出的多个**未冻结模块的必要增量**，但所有代码仍放回所属模块。跨模块调用只走第03份文档的公开接口，不跨表SQL。页面需要M01档案与M04状态时，分别实现或调用各自能力，再由只读组合接口组装。

已验收行为、路径和契约按交付子范围冻结，模块剩余范围继续开发。发现已验收页面缺陷交B会话；后续页需要扩展冻结接口时先由C形成兼容变更方案和独立工作包。C继续设计下一页。页面拆分不允许把修旧Bug和新业务混入同一个会话。

统筹开发管理依赖锁、路由装配、OpenAPI入口、迁移序号和共享组件。页面任务卡可以明确授权这些共享路径；并行开发使用独立工作目录，按已集成提交起步。无需为11个逻辑模块建立11个工程。

## 四 数据接口与运行方案

**业务数据。** PostgreSQL保存业务表与原始测量。ID建议UUID，时间用timestamptz并另存来源时区信息，金额以外的测量也使用BigDecimal和numeric；JSON十进制以字符串传输。质量判断在服务端或批准的设备端完成，前端只格式化显示。规则快照、原始记录、处置和审计各自保留版本。

**迁移。** Flyway管理增量SQL，文件名建议V202610100001__m01_catalog.sql，序号由统筹登记；已执行迁移不原地改写。不启动全量建表，仅建立当前页与基础能力需要的表。首次初始化、已有库升级、失败恢复分别验证；破坏性迁移另评审，恢复说明不能只写“回滚Git”。

**登录与权限。** 首期推荐本地账号、Spring Security、服务端会话，使用HttpOnly会话Cookie，生产HTTPS设置Secure与适当SameSite，写请求校验CSRF。推荐Spring Session JDBC保存会话，不为会话单独引入Redis。用户名、动作和工厂范围由后端校验。设备采用独立、可撤销且限定设备范围的凭据；不得混用人员会话或把明文密钥写入仓库。企业SSO如必需，在P01编码前替换方案。

**跨模块与事件。** 普通调用用同进程公开接口；测量落库与本模块outbox同事务，后台任务投递，消费者按事件ID去重。首轮不引入Kafka或RabbitMQ。接收持久化完成后才回成功，重发保持稳定键。MES未接入时相关块隐藏或标未开通，不能显示模拟成功。

**实时与历史。** 首轮推荐受控轮询，页面刷新间隔初值可设1秒供内部试验，正式目标待容量确认。设备采样频率、上传频率与页面刷新频率分别配置；不能把每秒一帧理解成每秒一条测量。趋势限制时间窗与点数，缩放查更细数据；原始记录及异常点仍可追溯。测量按设备/任务/时间建立索引；是否分区在容量评估后决定，不凭页面曲线数量估存储。

**容量估算。** 日记录数＝设备数×每设备实际入库频率×每日运行秒数；磁盘需加上多指标行、索引、事务日志、图像和备份。开发提交实测单条成本与余量，不把未计图像的粗算当采购配置。超时、数据陈旧、补传积压和磁盘不足必须可观察。

**文件。** 首轮附件用独立持久化目录加数据库元数据、摘要与授权下载；应用更新不能覆盖附件目录。需要多实例或独立对象存储时再评估，不把MinIO列成开工必需依赖。

## 五 环境部署与交付

开发环境支持现有Windows。正式部署优先建议客户允许的Linux LTS服务器，前端静态资源经反向代理访问同源API；后端JAR和PostgreSQL分别运行。若客户只允许Windows，采用JAR与经批准的服务管理方式，另验证开机启动和离线升级。Docker Compose作为允许容器环境的可选交付方式，不作为开发人员必须安装的前提。

建议开发端口为前端5173、API 8080、数据库5432；这些只是候选值，G00先检查占用，不停止其他项目。原型4174继续独立。测试与生产通过配置覆盖地址、端口、时区和存储目录，所有凭据走外部配置；不写死在页面。

现场包包含前端静态文件、可运行JAR、迁移、依赖与版本清单、配置样例、启动停止和恢复说明。图标、图表库和字体随包交付，不依赖现场能访问公共CDN。无外网时，构建端预备依赖和安装包，验证断外网启动。记录服务健康、数据库连接、采集积压、构建版本与请求追踪号。

备份覆盖数据库、附件及必要配置；测试恢复到隔离环境并核对任务—测量—报警关联。恢复点与恢复时间由确认项R01-Q07约定。本轮不承诺高可用集群、无限历史或既定毫秒延迟。

## 七 逐页开发与测试制度

完整27页清单、依赖和**当前可测试状态的唯一登记处**为 [页面开发与测试台账](12_页面开发与测试台账.md)。第07份回答“页面有哪些内容”，第12份回答“哪页现在能测、测到哪一级”。
