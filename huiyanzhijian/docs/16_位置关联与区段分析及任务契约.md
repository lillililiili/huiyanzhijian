## 3 位置关联契约

### 3.1 坐标和身份

material_coordinate_id代表一段明确物料的长度坐标，含spool_id、core_code、process_id、原点定义、正方向、单位m和版本。不能以显示盘号或“同为125米”判断同一物理位置。task_id引用冻结生产身份，上传端不再自由填写盘号/工序覆盖它。

pass_id代表一次授权检测遍次，由M02建立并关联任务；复检新建遍次，结束任务后的重检建新任务并关联原任务。position_segment_id代表本遍次内一段连续且换算一致的计米区段，由采集端分配稳定ID并向M04登记。换盘、计数器复位、回绕、方向切换、换算版本改变或无法确认连续性时必须开新段。倒退不把米数取绝对值后累计为新完成长度。

离线只使用已缓存且已确认的任务、遍次、坐标和profile；未知新盘先保存原文并隔离，不能自行借旧盘身份。计米重启若还能证明同一物料坐标可以续接新段；无法证明则UNKNOWN，不能自动从上一段末尾接上。

### 3.2 配置和记录字段

字段类型沿用第15份Id、Timestamp、Decimal、Sequence；COUNTER为有符号整数字符串，不能经JS Number截断。以下具名对象的全部字段均须出现，可空项用null。

| 对象 | 字段与含义 | 所有权及不可变边界 |
|---|---|---|
| position_profile | profile_id、version、device_id、position_source_id、source_kind、calibration_ref、calibration_valid_until、scale_m_per_count、direction_sign、sensor_offset_m、sync_method、max_sync_error_ms、max_position_error_m、approval_state | M01批准版本不可覆盖；参数未知为null，不能批准为已验证定位 |
| inspection_pass | pass_id、task_id、material_coordinate_id、pass_kind、supersedes_pass_id、selection_policy_version | M02；pass_kind为INITIAL/RETEST；选择政策不由设备自行指定 |
| position_segment | segment_id、device_id、task_id、pass_id、material_coordinate_id、capture_session_id、start_capture_sequence、profile_id、profile_version、counter_origin、position_origin_m、reason | M04追加；reason为START/RESET/WRAP/DIRECTION_CHANGE/CONFIG_CHANGE/CONTINUITY_LOST；同ID异内容409 |
| position_context | pass_id、material_coordinate_id、profile_id、profile_version、counter_value、counter_position_m、position_sample_time、sync_error_ms、uncertainty_m、direction、association_method | 测量1.1新增必填可空对象；引用与顶层position_segment_id一致；原字段position_m为补偿后检测点物料坐标 |

source_kind为ENCODER/METER/DEVICE_POSITION/ESTIMATED；sync_method为HARDWARE_TRIGGER/SHARED_SEQUENCE/TIME_MATCH/UNKNOWN；association_method同sync_method；direction为FORWARD/REVERSE/STATIONARY/UNKNOWN。不能因读到计米数就声明其同步准确。calibration_ref为M01管理的备案引用及摘要，不新增M01→M04附件依赖。

数值语义：scale_m_per_count须大于0；direction_sign只允许1或-1；sync_error_ms为同步时间差的绝对值，uncertainty_m及两个max误差限均须非负；sensor_offset_m及物料位置允许有符号，但必须符合已批准坐标范围。KNOWN要求以上适用参数均非空且方向/关联方式不为UNKNOWN，校准有效期按采样时刻校验，不能按补传到达时刻判失效。COUNTER来源还须有counter_origin和position_origin_m；缺任一必要依据即不得取得ELIGIBLE资格。Schema只校验表示形式，跨字段数值及来源条件由语义校验承担。

COUNTER模式以区段原点、计数差、profile方向符号和比例换算counter_position_m，再应用已验证符号约定的sensor_offset_m形成position_m。DIRECT设备米数原样保留在counter_position_m；raw保留厂商原单位及转换依据。固定偏移补偿仅适用于已验证布置和工况；存在伸缩、松弛、速度相关时延时不得继续套常数。复杂补偿必须使用独立方法版本及黄金样本。

### 3.3 位置质量和资格

1.1扩展position_quality为KNOWN/ESTIMATED/UNKNOWN/INVALID。KNOWN或ESTIMATED时position_m非空，context及segment引用齐全；UNKNOWN/INVALID时position_m为null，原计数/原读数仍留raw或context。KNOWN只表示已通过该版本资格检查，不表示无限精度。

KNOWN要求已批准且采样当时有效的profile、匹配坐标/遍次/区段、方向及同步依据可核实，实际误差指标未超批准界限。ESTIMATED保留估算值及依据，默认不纳入正式长度统计。无法验证的客户端KNOWN不能直接采信；原上传声明不改写，平台独立position_eligibility记录UNVERIFIED/ELIGIBLE/INELIGIBLE及原因。

定位误差以独立参考标记、仪器有效测量范围、不同速度/方向/启停工况实测。验收参数包括最大线速、最短目标缺陷、采样间隔、最大允许定位误差、重复性和同步误差。显示小数位不是误差指标；缺任何必需参数仅阻塞正式定位验收，不阻塞原文接收和模拟验证。

### 3.4 跨工序映射

M02维护版本化coordinate_mapping：源/目标coordinate_id、源/目标区间、映射方向、关系类型、依据、批准状态。首期可表达经批准的分段仿射映射、裁切保留段及反向；拼接是多段来源映射，空缺/歧义单列。区间使用半开形式[from,to)，保留原坐标不覆盖。

无映射或映射未批准时按工序分别展示，跨工序合并结果为UNAVAILABLE。映射生效后重算只产生新结果。一个目标区间多来源且无选择依据时不可自动去重；同一物料多遍检测也不按时间最后到达选择。映射查询为M02公开接口，M06不能直接联表推算物料关系。

M02公开DTO的完整字段定义为contracts/position-analysis中的MaterialCoordinate、InspectionPass、MappingVersion和SelectionVersion。MappingVersion.pieces逐段给源坐标、源起止、目标起止及方向；源和目标端点均升序，REVERSE按反向映射处理。一个SelectionVersion固定一个目标物料坐标，含task_ids、expected_intervals、pass_selections、批准状态和basis_ref；expected_intervals为null表示未知，空数组表示已知零长度。选择区间必须有来源且不冲突；其他坐标先通过指定批准映射转换，否则不可合算。同一遍次不因补传被重新挑选。

公开只读方法输入为可信工厂/环境上下文加对象ID和精确版本，返回上述DTO或明确NOT_FOUND/OUT_OF_SCOPE；设备只能查询已分配范围，人员按任务权限查询。字段数值顺序、引用归属、方向一致性及批准状态由语义校验实现，Schema合法不自动表示可以关联。

## 5 缺陷区段分析规则

### 5.1 输入集合和政策

分析必须固定任务、工序、线芯、物料坐标、指标/方法、遍次选择、位置映射版本、数据环境、采样窗口、应检区间和输入清单。正式集合仅取截至快照的有效资格记录、有效判定版本和合格位置资格；无效/缺测/隔离/估算分别统计，不能删掉后让覆盖看似完整。

M06分析政策包含policy_id/version、approval_state、support_mode、允许来源和位置资格、连续性上限、缺陷归并阈值、跨遍选择、重叠冲突政策及分母定义。APPROVED用于正式，TEST_ONLY仅模拟。support_mode首期POINT_ONLY或EXPLICIT_WINDOW：点模式只定位异常点，不产生正长度；窗口模式须有批准检测方法提供可证明的区间，不能由相邻两点自行插值。

政策默认keep_passes_separate，不跨遍汇总。需要选定复检结论时由授权人员或批准规则给出每区段选用遍次和依据，保留旧结果；不能默用“最新上传”。厂商直接输出窗口也要验证该窗口代表检测覆盖，而非仅数据统计窗口。

### 5.2 区间集合和比例

统一半开区间[from_m,to_m)，from<to；先映射到批准坐标，再与应检区间E求交。长度用精确十进制计算，最后显示舍入。无目标应检范围时长度比例为null/EXPECTED_RANGE_UNKNOWN。

| 量 | 定义与限制 |
|---|---|
| V有效覆盖 | 资格、位置、检测方法及连续性均满足的检测支持区间并集；不代表已判定 |
| D可判定范围 | V中存在批准PASS/FAIL判定的区间并集 |
| F不合格范围 | 选定遍次/版本下FAIL支持区间并集，与E相交 |
| P合格范围 | 在明确采用FAIL_WINS测试/批准政策时，PASS支持区间并集减F；其他冲突政策需另版 |
| U未判定长度 | E减D；包含无覆盖和有覆盖但无判定，明细分别列出 |
| 有效覆盖率 | length(V)/length(E)；E长度0时null/ZERO_DENOMINATOR |
| 按长度合格率 | length(P)/length(D)，同时返回U；D长度0时null，不返回100% |
| 检测点合格率 | PASS数量/(PASS＋FAIL数量)，另列有效但未判定点；不以所有VALID点作分母 |
| 整盘合格率 | 批准范围内已正式判定合格盘数/纳入范围盘数；未判定盘单列，不能用点比例代替 |
| 成材率 | 依赖投入、合格产出、裁切报废返工及物料映射；数据未接齐时UNAVAILABLE |

在FAIL_WINS政策下要求D=P∪F且P∩F为空，D⊆V⊆E。同一范围重叠不重复累加；多指标仅在坐标、适用性、方法和选择政策明确时作交并，不能将不同工序同米数强行合并。首期综合页分别展示三指标，不默认给总体放行率。

### 5.3 点 区段和聚类

缺陷点保存record_id及位置；缺陷区段由有证据的FAIL支持区间组成，包含区间、长度、指标、证据记录及判定版本。首期merge_gap_m=0，只合并相交或相接且无连续性屏障的同类区间。

若以后允许跨小间隙聚类，cluster_span可以包含间隙，但defect_length仍计算FAIL区间并集；不能把正常或未测间隙计入缺陷长度。缺测、无效、计米复位、方向切换、坐标不一致、不同遍次及规则变化均是默认屏障。重检不会删除历史缺陷，只影响批准的结果选择。

### 5.4 可手算测试向量

以下为SIMULATED/TEST_ONLY，窗口支持被测试夹具明确声明为有效；不代表任何真实仪器能覆盖这些区间。标准区间单位m，E=[0,10)。

|---|---|---|
| V01 | PASS[0,4)，FAIL[4,6)，PASS[8,10) | V=D=8，P=6，F=2，U=2；覆盖80%，长度合格75% |
| V02 | V01再加入FAIL[5,7) | V=D=9，P=6，F=3，U=1；覆盖90%，长度合格6/9，显示66.67% |

| V05 | PASS[0,6)，FAIL[4,8)，FAIL_WINS | V=D=8，P=4，F=4，U=2；长度合格50% |

### 5.5 区段验收

SEG01—SEG08分别执行V01—V08并核对区间、长度、分子分母、排除原因和证据ID。SEG09执行两指标重叠、跨工序无映射及复检选择，要求按批准范围去重、缺映射拒绝合并、旧缺陷可追溯。SEG10把数据按不同到达顺序/批次重放，固定输入清单及政策时结果和摘要一致；断点、规则边界不被合并跨越。

## 6 分析任务契约

### 6.1 外部接口

均为人员会话与服务端范围授权，设备凭据不得调用。沿用第05份响应信封、CSRF/If-Match与Idempotency-Key，具体身份实现由G00验证。写请求结果未知时原幂等键重试，不自动新建分析任务。

| 操作 | 请求及响应 | 错误和幂等 |
|---|---|---|
| POST /api/v1/analysis-jobs | AnalysisRequest；202返回job_id、state=QUEUED、version及请求摘要 | 同工厂＋操作＋Idempotency-Key同内容返回原任务，异内容409；越权403，未知范围422 |
| GET /api/v1/analysis-jobs/{id} | JobView，进度/阶段/错误/输入摘要/结果/新鲜度 | 不存在或范围外404；GET无写入 |
| POST /api/v1/analysis-jobs/{id}:cancel | reason，If-Match及幂等键；200任务状态 | 终态409；重复同键回原结果，过期版本412 |
| POST /api/v1/analysis-jobs/{id}:retry | reason，If-Match及幂等键；200原job新attempt或原已执行命令结果 | 仅可恢复FAILED；保持原已冻结输入和政策，耗尽或永久错误409 |
| GET /api/v1/analysis-results/{id} | 结果元数据、统计、manifest摘要和范围 | 只有完整提交结果可读；暂存结果不可见；范围外404 |
| GET /api/v1/analysis-results/{id}/segments | cursor、limit≤500、类型筛选；稳定顺序分页 | 游标绑定结果及筛选；不可用游标400 |

AnalysisRequest字段：schema_version=1.0、kind=SEGMENT_ANALYSIS/LENGTH_STATISTICS/REPORT_GENERATION、task_ids（1—100不重复）、data_environment、sample_from/to（含时区）、received_cutoff、selection_id/version、analysis_policy_id/version、mapping_version_ids（可空数组）、report_template_version（非报告为null）、reason。工厂和actor由服务端确定。任务ID范围不能隐含所有盘；同请求有越权任务整包拒绝。

另有必填可空supersedes_job_id，显式重算时关联原任务；未关联为null。报告结果包含report_id，非报告结果为null。首次创建202状态QUEUED；同幂等键重试返回原job的当前状态，不强制将已完成任务退回排队。任务响应ETag为带引号的version，取消/retry使用If-Match；分页接口按固定结果的坐标/遍次/from_m/segment_id稳定排序，metric_code筛选绑定游标。

selection引用已批准/测试的应检范围、坐标和遍次选择；请求不得直接自报expected_length绕过依据。时间窗口为[start,end)，received_cutoff只是请求过滤条件，不单独构成一致性快照。

JobView至少含job_id、kind、state、version、attempt、phase、processed_items、total_items（未知null）、manifest_id/hash（冻结前null）、result_id（成功前null）、freshness、error_code、retryable、created_at、started_at、finished_at、next_attempt_at。错误为INPUT_NOT_READY/POLICY_NOT_APPROVED/POSITION_CONTEXT_MISSING/MAPPING_UNAVAILABLE/DEPENDENCY_UNAVAILABLE/LEASE_LOST/RESOURCE_LIMIT/CANCELLED/INTERNAL_ERROR；用户信息不暴露内部堆栈。

### 6.2 一致性输入快照

QUEUED→PREPARING时，M06通过M04公开SnapshotApi.prepare/getManifest/readChunk固定输入，不跨表SQL。M04在一致性数据库读取视图中生成不可变清单，包含record_id、资格修订、判定版本、位置资格修订、证据引用及有序分块摘要；仅比较序列号或received_at不足以解决未提交事务穿越截止点的问题。

M06再冻结M02身份/选择/映射版本、M03规则、M06政策/模板及M05相关事件处理证据，组成复合manifest。无跨模块全局事务假设：这些版本通过公开API读取并验证；最终报告需要M05确认清单内全部相关事件已处理、必要复核已结束，否则保持WAITING_INPUT。不能用“最大事件ID已消费”替代无缺口水位。

PREPARING阶段成功落下复合manifest后不可替换。尚未冻结即失败时retry会重新准备，以最终manifest为明确快照；已冻结后所有attempt使用同一清单。需要纳入新数据或政策时必须以新幂等键创建新job，并记录supersedes_job_id关联，不能把retry变成重算最新数据。

补传/更正/位置资格变更由所属模块outbox触发M06范围失效标记；M06定期通过公开版本查询补偿漏消费。freshness=CURRENT/OUTDATED/UNKNOWN独立于执行状态。CURRENT指截至last_checked_change_version的已核实状态，不是未来永远不会迟到。旧结果仍可读但标过期；正式发布再核对相关版本/水位并冻结发布依据。发布后迟到不改旧报告，只产生数据变更提示和重出版本。

### 6.3 状态 租约和失败恢复

状态：QUEUED→PREPARING→RUNNING→SUCCEEDED；准备条件不足进入WAITING_INPUT，具备条件后重回PREPARING；临时故障进入RETRY_WAIT，到期继续原阶段；永久错误或次数耗尽进入FAILED。QUEUED/WAITING_INPUT/RETRY_WAIT可直接CANCELLED；运行中进入CANCEL_REQUESTED，由worker确认后CANCELLED。成功/取消/失败均保留历史attempt。

领取任务使用数据库原子条件更新和lease_token/lease_until；每次领取增加fencing_token。续租、写进度、提交结果必须核对token。旧worker即使算完也不能提交。到期扫描恢复任务，尝试次数有上限；默认开发并发1、租约60秒、20秒续租、最多3次，生产值通过压力测试确定。取消和成功提交在同一行锁/CAS上竞争：先提交的一方确定结果，不能同时成功和取消。

结果分块先写临时位置，仅在摘要/数量校验完整后，M06事务提交result、任务成功状态及outbox，再对外可见；孤儿文件可对账清理。不把中间进度当成功，total未知时不编造百分比。幂等键保留与任务生命周期一致；归档保留索引或明确拒绝过期重放，禁止清掉键后静默重复创建。

| 编号 | 输入或故障 | 通过条件 |
