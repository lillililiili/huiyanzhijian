# B1 数据库物理设计与日志方案

2026-10-21；后端、数据库、设备模拟器基础包。开发完成待用户验收，未冻结。只覆盖35—220kV的金属屏蔽搭盖率、铜丝屏蔽相邻间隙、电缆不圆度。

## 1. 本次架构与部署边界

Node.js 22.23.2容器、TypeScript 5.9.3、NestJS 11.2.7、pg 8.23.1、PostgreSQL 16。完整依赖版本由两份package-lock.json锁定。Node在此负责业务鉴权、协议校验、事务写入和查询，测量算法与实时硬件采样不迁入Web服务。

按用户授权使用本机postgis/postgis:16-3.5，不自动拉取新镜像。镜像初始化自带PostGIS等扩展，B1业务没有使用空间字段或函数；不是项目已选定GIS依赖。生产PostgreSQL版本仍需专项确定与验证。

目标是前端、后端、模拟器三个独立应用容器，数据库是另一个基础设施容器。本期只建设后端和模拟器，既有前端容器/代码保持原状，不能宣称前端三端联调完成。模拟器只通过HTTP向后端提交设备输入，不能直连PostgreSQL或代替操作员创建工单。平台人员API创建工单、盘号、任务；后端是共享业务事实的唯一写入入口。

后端容器内API和analysis-worker是两个独立Node进程，由supervisor拉起。worker本期只写健康心跳，不运行分析任务、不消费outbox。进程退出互不阻断，但共享容器资源和故障域；生产CPU/内存限额、队列积压、容量及故障切换仍待验证。尚无Redis/RabbitMQ/Kafka，也未拆微服务。

## 3. 数据链与准确性

1. 人员API核对工单—盘号—规格—工序—设备—指标相容性。任务创建时冻结规则和上下文快照；开始任务后生成绑定版本，设备I04确认后才可验证该绑定下的采样。
2. 入站先检查身份、来源环境和整批设备作用域，再逐条校验Schema、单位、原文版本、时间窗、绑定和采集序号。不把HTTP 200视作每条都存储成功，设备读取逐条收据。
3. 同一个数据库事务写入measurement_record、value、evaluation、qualification、outbox。成功收据只在该事务提交后产生。批内可部分成功；发生未知故障返回UNKNOWN，设备保留原记录键重试或查询I08。
4. 原始对象保存在raw_payload JSONB，含来源声明、raw、十进制字符串和微秒时间。它保留JSON语义，**不是原HTTP字节存档**，不保留空白和键顺序。重复属性、非法代理字符和超限数值先拒绝。原始字节级取证若成为要求，另建受控对象存储与摘要，不修改本表已有事实。
5. 原始值、来源判定、平台判定、业务资格分开。INVALID/MISSING值必须NULL，不能补零；恢复或复核应追加版本，不能覆盖原超限。B1只生成判定/资格版本1，未提供人工修复、解除隔离或重算API。
6. 规则为TEST_ONLY，正式来源不能使用演示阈值取得生产合格结论。没有有效规则则NOT_EVALUATED。任务ENDED仅表示结束；不是整盘PASS。

### 精度、时间和位置

- 测量值/位置/计划长度numeric(24,10)，14位整数、10位小数；接口用十进制字符串，阈值比较使用Decimal。展示小数位不改变存储事实。
- 捕获序号numeric(20,0)，限制uint64范围；不转JavaScript Number。独立保留供应商序号、采集会话和传输连接。
- sample_time/received_at为timestamptz(6)。采样微秒原文和DB值对账；不是仅测JavaScript毫秒显示。工厂时区用于后续统计显示，不能改变原时刻。
- position_m是来源报告的米数，position_eligibility固定UNVERIFIED。模拟器步长仅测试输入，不是编码器验证。本期没有1.1位置段、回退/打滑校正、全长覆盖、缺陷区间合并或成品率算法；双向测径也不视为全周不圆度测量。

### 去重与并发

- 测量唯一键：(factory_id,device_id,source_record_key)，另以(factory_id,device_id,capture_session_id,capture_sequence)防止换记录ID重复采样。相同规范化内容返回首次收据；异内容写冲突摘要并保留原记录。当前冲突表不保存第二份完整冲突报文。
- capture_session与record_id在模拟器重试、离线排队和重启时不变。batch_id代表传输尝试，不用作测量去重键。
- binding_ack以(device_id,id)为主键，允许不同设备使用同一厂商本地确认号；迁移002修正初版全局键过强的问题。
- 人员命令按工厂/人员/Idempotency-Key储存原结果；改内容重用键拒绝。任务状态变化需If-Match；设备只能有一个RUNNING任务，由事务锁与唯一索引双重保护。
- 当前设备停用后禁止新写及历史补传。重新授权的历史导入/复核是后续业务，不能为方便补传绕过停用权限。

## 4. 索引、分页与未来数据量

已有任务/采样时间、设备/入库顺序、隔离待处理、接入错误、审计请求与时间、事务事件顺序索引。测量列表采用签名游标，固定工厂、筛选条件和入库序号上界，页面中途新增不混入本次分页；上限100。后续判定版本变更还需分析快照，当前列表只显示版本1。

暂不做按日分区：须先确认设备频率、单条大小、保留期、并发读取和全球唯一键要求，再设计分区/归档及基准测试。不能仅加分区名就宣称高吞吐。当前每设备写入串行化、批量逐条事务、接入凭据120请求/分钟是测试底座；不是生产吞吐承诺。高频采集需基于样机实测速率调整聚批、事务成本、连接池和背压。

## 5. 三类日志与追查

| 类别 | 存储 | 本期能回答的问题 | 保留与权限 |
|---|---|---|---|
| 业务审计 | m00.audit_event | 谁登录/退出、创建工单盘号任务、开始结束、打开设备会话、确认哪份绑定 | 追加写；admin按工厂读取；匿名登录失败factory_id为空，只能受控运维查库 |
| 接入诊断 | m04.ingestion_batch/item/conflict | 哪次请求、哪条输入、首次ID、重复/隔离/拒绝原因、同键冲突 | 业务事实不自动清理；admin查批次，设备I08查自身来源键 |
| 运行日志 | stdout JSON与Docker日志 | 请求号、HTTP状态/错误码、耗时、启动/数据库连接异常、进程退出 | Docker每容器10MB×5滚动；不等同永久审计 |

不记录密码、Cookie、Bearer值或整个请求体到运行日志；审计仅保存必要业务字段。客户端X-Request-Id经格式校验后用于关联，不作权限凭证。工单、盘号、任务、设备会话和绑定确认的审计与其业务事务一起提交；人员登录/退出的会话变更和审计当前为顺序提交；技术运行日志不阻塞事务。

接入批次、逐条诊断和测量事务并非一个大事务。极端崩溃可能留下PROCESSING批次，或已写测量而逐条诊断尚未写入；以I08与测量唯一键对账，不能用批次“未完成”认定没入库。后续应增加处理中超时巡检、重试队列告警和可追查的运维处理流程。

保留期、法律归档、存储预算、删除审批、脱敏检索以及日志集中采集仍待明确。B1不自动删除业务原文；这意味着长期运行会增长，须在生产前完成容量/归档方案。SQLite模拟器也保留样本和delivery_attempt，不静默丢弃失败项。

## 6. 账号、迁移、备份与恢复

- 运行账号hy_runtime无建表/删除权限；原始事实、规则、审计、快照等表撤销UPDATE。迁移专用凭据不注入常驻后端。**本机容器的hy_migrator是镜像初始化管理员（superuser）**；生产应进一步分离初始化管理员、DDL owner、备份与运行角色，不复用此本地管理员配置。
- SQL编号001、002均在事务内执行，数据库保存文件SHA-256，已执行文件不能改写，新增变更用下一迁移。启动后端不自动迁移、不补业务种子。bootstrap仅首次插入固定档案，重复运行不重置用户密码和既有数据。
- 随机本地口令位于runtime/b1/access.json与env文件，不输出到验收报告。Windows的文件mode不代表已经建立生产ACL；目录不可对外分享或纳入Git。
- `node tools/b1.mjs backup`生成pg_dump自定义格式到runtime/b1/backups。容器测试实际恢复到新的隔离库，逐条摘要汇总与记录数相同，迁移记录也保留。源库未被覆盖。
- 本次验证的是本机逻辑备份恢复，不证明PITR、跨机灾备、RPO/RTO、24小时稳定性或性能SLA。生产还需WAL归档、备份加密、异机恢复演练与监控。
