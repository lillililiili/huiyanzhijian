# Implementation contracts

This file describes the existing local prototype at cbd8c76, not production API contracts. Production design and known differences are in [page mapping](../docs/07_原型页面与开发映射.md), [business rules](../docs/08_业务规则与验收基线.md), and [review log](../docs/09_文档审查与开发任务.md). Demo roles, state, storage and measurement rules are not approved production behavior.

Buildless native HTML/CSS/JS. Namespace `window.HY = { Pages:{}, Actions:{} }` created in data.js. Scripts load data.js, ui.js, pages-core.js, pages-management.js, app.js in that order.

## Store (data.js)
`HY.Store.state` contains arrays: tasks, specs, devices, records, alarms, recipes, reports, audits, users; objects: settings, mes, connections, reportTemplate. `HY.Store.metrics` contains dg,jx,by objects {id,name,short,unit,threshold,operator,color,icon,image}. metric image paths: assets/images/copper-inspection.png, wire-inspection.png, roundness.png. device images device-dg.png, device-jx.png, device-by.png. logo assets/images/logo.png, products.png, login-background.png, metric-dg.png, metric-jx.png, metric-by.png.
Store functions: `save()`, `reset()`, `log(action,detail)`, `id(prefix)`, `task(id)`, `spec(id)`, `device(id)`, `recipe(id)`, `record(id)`, `alarm(id)`, `recordsFor(taskId)`, `currentRecords(metric?)` (30 min/current tasks), `stats(records)` -> {total,valid,invalid,pass,fail,min,max,avg,last}, `judge(value,metric,rule?,validity?)` -> pass/fail/invalid, `createTask(input)` -> task, `startTask(id)`, `advanceTask(id)` adds deterministic records, `completeTask(id)`, `updateAlarm(id,{status,note,actor?})`, `reviseRecipe(id,input)`, `createReport(taskId)` -> report with snapshot, `retrySync(recordIds?)`, `importRecords(rows)` -> {count,errors}, `setScenario(name)` -> offline/invalid/mes-failure/normal. Mutators log/save; functions throw Error for invalid input.

Fields: task {id,workOrder,reelId,specId,metric,deviceId,recipeId,ruleSnapshot,status:pending/running/completed,startAt,endAt,plannedLength,measuredLength}; spec {id,voltage,area,cores,structure:tape/wire,metrics:[dg,jx,by],enabled}; device {id,name,metric,line,status:online/offline,source,lastSeen,calibration}; record {id,taskId,metric,deviceId,reelId,workOrder,time,meter,value,validity:valid/invalid,judgement:pass/fail/invalid,ruleSnapshot:{id,version,threshold,operator},image,source,platformStatus:received/pending,mesStatus:confirmed/pending/failed,receivedAt,confirmedAt,aux:{...}}; alarm {id,recordId,taskId,metric,active:boolean,status:pending/processing/resolved,createdAt,note,history:[{time,actor,note,status}]}; recipe {id,metric,version,threshold,operator,name,enabled}; report {id,taskId,kind:stage/final,createdAt,snapshot:{task,records,alarms,stats,template}}. Names/labels resolve via metrics map.

## Pages/events
Pages return HTML via `HY.Pages.dashboard=()=>...`, with current context `HY.route` and `HY.params` URLSearchParams. Hash routes like #task?id=T20261009001. `HY.navigate(route)` updates hash. `HY.render()` redraws shell/page and charts. `HY.filters` page/form local query states. `HY.Actions['name']=(element,event)=>{...}` called for [data-action]; data args exposed via element.dataset. Form [data-filter] automatically stores FormData into HY.filters[id], resets page, calls HY.render. U.modal callbacks should call HY.render themselves when successful. Navigation links #... handled normally. Actions must be functional. Escape any user data.

Routes core: login (root handles), dashboard, monitor, detection (metric=dg/jx/by), tasks, task?id, specs, history, trace?reel, import.
Routes management: alarms, alarm?id, analytics, reports, report?id, metrics, recipes, templates, devices, connections, mes, sync, users, audit, settings.
